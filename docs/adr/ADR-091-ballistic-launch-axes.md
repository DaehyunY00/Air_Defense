# ADR-091 — 탄도 축선 발사점 연장: 탐지 선착이 규칙이 아니라 기하에서 나오게 한다

- 상태: 채택
- 일자: 2026-08-25
- 관련: ADR-090(조기경보 보고원 — 본 ADR의 전제 문제) · ADR-064(남부축 dwell 스케일 — 같은 규율) · ADR-063(표적 산포 — 불변 유지)
- 플래그: `ballisticLaunchAxes` — **엔진 기본 OFF**(불변 규칙 1 · 재기준선 대상) · [지휘 흐름] 프로토타입만 기본 ON(`?lx=0` 해제, 칩 상시 표기)
  - **추기(2026-09-01)**: 프로토타입도 **기본 OFF**로 되돌렸다(`?lx=1`로 켬). 사용자 결정 — ADR-090 추기와 같은 규율.

## 맥락 — 종말 구간만 흘리는 모델에서는 조기경보가 성립하지 않는다

종전 모델은 탄도 위협을 축선 **진입점**(표적에서 59~198km)에서 스폰했다. 위협 제원의
사거리밴드(srbm 400~690km·mrl 350~400km)는 궤적에 쓰이지 않았다(threats.js에 명기).
그 결과:

- 모든 센서가 **첫 스캔 틱부터 동시에** 볼 수 있어 탐지 선착이 난수 추첨이 됐고,
  실측에서 srbm 최초 탐지 26/27이 포대 MFR이었다.
- 그린파인 900km 조기경보의 몫 — 「발사 직후 원거리 최초 탐지 → KAMDOC 큐잉 → 포대는
  종말 단계에 획득」이라는 실제 KAMD 시퀀스 — 이 모델에 존재하지 않았다.
- ADR-090이 보고원 규칙을 고쳐도, 그린파인이 **먼저 보는** 그림은 나올 수 없었다.

사용자 결정: 정합성이 최우선이며 실제 방공 시스템 운용과 같아야 한다.

## 결정

`ballisticLaunchAxes`(기본 OFF)를 둔다. ON이면 탄도 위협(srbm·mrl_large)에 한해:

1. **발사점 연장** — 대표 사거리 `rep = rangeBandKm 중앙값`(srbm 545·mrl 375)이 축선
   개념거리 `conceptReachKm`보다 길면, 그 차 `ext`만큼 진입점 **뒤쪽**(축선 직선의 연장선,
   표적 반대 방향)에서 비행을 시작한다. `KJ.ballisticLaunchExtension(type, axis)`:

   | 축선 | srbm | mrl_large |
   |---|---|---|
   | central(140km) | +405km ×3.89 | +235km ×2.68 |
   | east(200km) | +345km ×2.73 | +175km ×1.88 |
   | southcentral(306km) | +239km ×1.78 | +69km ×1.23 |
   | southeast(394km) | +145km ×1.36 | 연장 없음(rep ≤ 축선거리) |

2. **체공시간 동비율 연장** — `dwellSec × (reach+ext)/reach`. 함의 속도를 유지하는
   ADR-064 남부축과 같은 규율이다(예: srbm central 90→350초, 실제 KN-23 비행시간 수 분과
   부합).
3. **위치 재매개변수화** — `iadsThreatPosition`이 발사점→표적(산포 착탄점 포함)을
   보간한다(진행률을 발사점 기준으로 당기는 `p' = p·f − (f−1)`, f=(L+ext)/L). 표적·산포
   (ADR-063)는 불변. 고도는 `threatPhysics`에 전체 사거리(L+ext)를 넘겨 정한다(장사정일수록
   높은 정점 — 기존 scale 규칙 그대로).
4. **새 난수 소비 없음** — ext는 타입×축선 상수라 결정론이고, CRN 쌍대(같은 seed의
   As-Is·To-Be가 같은 위협열)를 흔들지 않는다.

발사점 좌표는 실제 발사원점이 아니라 축선 연장선 위 **개념좌표**다(전 좌표 개념값 정책
동일 적용).

## 수치 영향 (실측 — SC3·seed 12345·600초, ew·lx ON)

- **OFF bit-exact**: 결과 SHA-256 변경 전과 동일(asis `ae64a536…`·tobe `a3ad455a…`).
- **탐지 선착이 물리에서 나온다**: srbm 최초 탐지 **그린파인 26/27**(종전 MFR 26/27),
  다음 센서까지 리드타임 **중앙값 203초**. mrl_large는 FPS117이 최초(49/49) — 정점이 낮아
  그린파인 minAltitude(5km) 게이트를 FPS117(1km)보다 늦게 넘는 기하의 귀결이다.
- **조기경보가 시간을 벌어준다**: 탄도 누수 asis 33→11·tobe 26→6. 격추 asis 46→49·
  tobe 53→55. 관측창(600초)보다 비행이 길어져 **관측종료 미해결 26건**이 생긴다(해결분
  기준 지표 정의 — README 「요격 실패율 읽기」 그대로 적용).
- 양 모드 탐지열은 동일(센서 스트림 CRN 공유) — Δ 비교 전제 유지.

## 한계·후속

- **기준선·실험보고서는 OFF 기준이다.** 이 플래그를 기본 ON으로 승격하려면 기준선 6케이스
  재수립과 paired 실험 전면 재실측이 선행돼야 한다(ADR-065의 전례).
- 본 앱(index.html) 지도 애니메이션은 `KJ.axisPosition`(클램프)을 쓰므로, 플래그 ON 실행을
  지도에 얹으면 진입 전 구간이 진입점에 고정되어 보인다 — 본 앱 연동 시 함께 고칠 것.
- ABT(항공기·순항·무인기)는 대상 밖 — 진입점 스폰이 영공 진입 탐지라는 해석으로 유지.
- 관측창 600초는 연장된 비행(최대 350초)과 조합하면 후반 스폰이 미해결로 남는다.
  장기 관측이 필요하면 `dur`을 늘려라(프로토타입 `?dur=`).

## 되돌리는 법

`ballisticLaunchAxes` 미지정(기본 OFF)이면 종전과 bit-exact. 프로토타입은 `?lx=0`.
