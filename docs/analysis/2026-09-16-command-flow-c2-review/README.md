# 지휘흐름 단일본 C2 검토

검토일: 2026-09-16 · 기준 커밋: `12d14e0` · 대상: `K-JAMDS_지휘흐름_단일본.html`

> 이 문서는 수정 전 상태의 검토 기록이다. 후속 구현 정정과 범위는
> [ADR-100](../../adr/ADR-100-c2-state-and-observation-integrity.md)을 참고한다.
> 동봉한 원시 수치는 위 기준 커밋에서 측정했으며, 재현 스크립트를 수정된 소스에서 실행하면
> 현재 결과가 나온다. 과거 결과를 현행 성능값으로 인용하지 않는다.

**판정: 지휘흐름 설명과 병목 가설 탐색에는 유용하지만, 현재 상태로 C2 구조의 효과를 정량 입증하기에는 부족하다.** 특히 화면 기본값과 실제 결심시간 설정의 불일치가 확인되어, 기존 단일본 실행을 결심시간 동일 조건의 비교로 해석하면 안 된다.

검토는 단일본 생성 정합성, 내장 코드 실행, 공통 엔진·정책·계측 코드, 설계결정 기록, 관련 회귀검사에 근거한다. 프로그램은 수정하지 않았다. 브라우저 연결을 사용할 수 없어 실제 화면 배치와 클릭 조작은 확인하지 못했다. 아래 화면 관련 판정은 표시 코드와 그 입력값을 대조한 결과다.

공개 기준으로는 정보 공유·권한·분산 실행·단절 시 지속성을 강조하는 [NATO IAMD Policy, 2025, 20·30·31항](https://www.nato.int/en/about-us/official-texts-and-resources/official-texts/2025/02/13/nato-integrated-air-and-missile-defence-policy)와, 구현 검증과 특정 사용 목적에 대한 현실 타당성 검증을 구분하는 [DoDI 5000.61, 2024](https://www.esd.whs.mil/Portals/54/Documents/DD/issuances/dodi/500061p.pdf)를 참고했다. 이 기준은 평가 관점을 제공하며, 저장소의 한국군 조직·절차 가정을 인증하지 않는다.

## 핵심 발견

### 1. [P1 / 재현] 기본 화면의 ‘결심 시간 동일화 ON’이 실제로 적용되지 않는다

`prototype/command-flow.html:1523`의 `par` 기본값은 숫자 `1`이다. URL에 값이 없으면 `1531`에서 이를 그대로 사용하고, `features()`는 `1386`에서 그대로 전달한다. 반면 `js/config/deployment-adapter.js:664`는 `=== true`로 검사한다. 따라서 기본 실행은 카탈로그의 동일화가 꺼지고, 사용자가 명시적으로 `?par=1`을 주면 파서가 불리언 `true`를 만들어 동일화가 켜진다. `activeConfigChips()`는 두 경우 모두 ON을 표시한다.

**저장된 단일본의 인라인 스크립트 15개를 직접 적재해 확인했다.** SC3·LEGACY·seed29·600초에서 다음과 같다.

| 실행 | 실제 `par` 값 | IAOC 운용자 성분 | IAOC 총 평균 처리시간 | 생성 / 격추 / 누수 / 종료 미해결 |
|---|---|---:|---:|---|
| URL에 par 없음, 기본 실행 | 숫자 `1` | 1초 | 2.5초 | 89 / 30 / 27 / 32 |
| 명시적 `?par=1` | 불리언 `true` | 30초 | 31.5초 | 89 / 29 / 28 / 32 |

이는 수치 하나의 차이보다 **실험 조건 표시가 실제 모델과 다르다**는 점이 중요하다. 단일 seed의 격추 차이는 효과 추정치가 아니다. `tests/c2-decision-time-parity.test.mjs`는 불리언을 직접 전달하므로 통과해도 기본 화면의 설정 변환 결함을 발견하지 못한다.

필요 조치: 입력 타입과 최종 적용 설정의 일치 보장, 기본 URL과 명시적 기본값 URL의 동치 확인. 기존 결과에는 실제 적용된 카탈로그 값을 함께 확인해야 한다.

### 2. [P1 / 경계조건 재현] 한 계통의 포화가 다른 계통의 처리까지 중단시킨다

`js/engine/sim-engine.js:917`의 분기별 실패 예외는 `iads_track`, `directive_reception`, `approval`에만 적용된다. 새 작업인 `approval_return`, `directive_relay`, `directive_issue`는 포화 시 공통 위협 객체에 `pipelineDead=true`를 기록한다.

동일한 포화 노드에 실제 `_nodeArrive` 메서드를 호출한 결과:

| 작업 종류 | 드롭 후 `pipelineDead` |
|---|---|
| 항적 처리 / 명령 접수 / 승인 | false |
| 협조 회신 / ICC 중계 / 명령 발령 | true |

후속 결심은 `2463`에서 해당 공통 상태를 보고 종료한다. 독립된 다른 계통도 영향을 받으므로, 국지적인 처리 실패를 전역적인 대응 불능으로 확대할 수 있다. 기존 코드의 “한 분기 포화가 다른 분기를 죽이면 안 된다”는 주석과도 어긋난다.

**기본 600초 양 모드 실행에서는 포화 드롭이 0건이었다.** 이 결함을 기본 실행 결과의 원인이라고 주장하지 않는다. 부하·포화 조건을 연구하는 시뮬레이터의 경계조건 결함이다.

### 3. [P1 / 경계조건 재현] 오래되거나 역순으로 도착한 교전현황이 현재 상황으로 채택된다

`js/engine/sim-engine.js:2134`는 생성 후 유효시간을 넘긴 메시지를 `stale`로 집계하지만, `2140`은 유효기간을 수신 시점부터 다시 부여한다. 소비 함수 `2072`는 생성 후 경과시간을 확인하지 않는다. 같은 발신자의 최신 상태를 과거 메시지가 덮어쓰지 못하게 하는 검사도 없다.

실제 메서드로 확인한 사례:

- 생성 0초, 수신 500초, 유효기간 300초의 상태가 `stale=1`로 집계되면서 800초까지 유효해졌다. 799초에도 결심에 사용 가능한 상태로 반환되었다.
- 최신 `released` 상태 뒤에 더 오래된 `assigned` 상태를 전달하면 과거 상태로 되돌아갔다.

해당 상태는 `2469` 이후의 중복해소·결심 보류 조건에 사용된다. 따라서 정보의 신선도와 메시지 순서가 C2 행동에 올바르게 반영되지 않는다. 이 역시 기본 600초 실행에서는 발동하지 않았고, 지연·순서 역전 경계조건에서 확인한 결함이다.

### 4. [P2 / 재현] 전체 항적과 표시 표본의 분모가 다르며 종료 미해결을 결과줄에 표시하지 않는다

`prototype/command-flow.html:1581`은 항적 상세 기록을 300개로 제한한다. `1618`은 그 기록 개수를 전체처럼 ‘항적’으로 표시하며, `1619`는 `flowTruncated`만 확인한다. 별도 `traceTruncated`는 표시하지 않는다.

정확한 화면 기본 기능 조합에서 관측시간만 3600초로 늘린 As-Is 실행은 **생성 455 / 상세 기록 300 / 격추 170 / 누수 243 / 종료 미해결 42**였다. `traceTruncated=true`이고 `flowTruncated=false`였다. 따라서 코드상 상태줄은 ‘300개 항적’과 ‘격추170 / 누수243’을 절삭 경고 없이 나란히 표시한다. 상세 기록 기반 지도·항적 목록·복수 사수 집계와 전체 노드 흐름·결과 합계가 서로 다른 집단을 사용한다.

기본 600초 실행에도 종료 미해결이 적지 않다.

| 모드 | 생성 | 격추 | 확정 누수 | 종료 미해결 |
|---|---:|---:|---:|---:|
| As-Is | 89 | 27 | 29 | 33 |
| To-Be, 실제 기본 설정 | 89 | 30 | 27 | 32 |

엔진은 `censoredRaw`를 제공하지만 결과줄 `1620`은 이를 표시하지 않는다. 미해결은 성공도 실패도 아니다. 전체 생성·확정 결과·미해결·표시 표본을 구분해야 결과와 화면의 범위를 알 수 있다.

### 5. [중요 모델 한계] To-Be의 도메인 제대 부하가 실제 판단 권한을 입증하지 않는다

`js/engine/sim-engine.js:1066`은 To-Be 한국군 주축의 전역 책임 C2를 IAOC로 정한다. MCRC·KAMDOC는 `1151` 이후에서 지연 0의 병렬 통보를 받고, `1181`의 완료 콜백은 로그만 남긴다. 이 처리 결과는 후속 결심의 조건이 아니며 포화도 결심을 막지 않는다고 `1148`에 명시되어 있다.

이는 ADR-078에 기록된 **의도된 개념화**다. 모든 하위 제대를 반드시 직렬 경유시켜야 한다는 뜻은 아니다. 다만 현재 구조에서 보여 준 것은 하위 제대의 통보·부하이며, 그 제대의 식별 판단, 권한, 이견이 합동 결심에 어떻게 영향을 주는지는 충분히 검증하지 않는다. ‘제대가 화면에 존재함’과 ‘제대가 결정에 기여함’을 구분해야 한다.

### 6. [중요 모델 한계] C2가 가진 정보·권한과 모의세계의 실제 상태가 충분히 분리되지 않는다

- `js/engine/sim-engine.js:1685` 이후는 C2 처리 완료 시 출처·융합 항적을 일괄 `CORRECT/HOSTILE`로 확정한다. 불확실한 식별이 판단을 지속적으로 제한하는 구조가 약하다.
- 신선도는 `1658`에서 도착 시 검사하지만 이후 반복 결심에서는 원장 신선도를 같은 방식으로 재검증하지 않는다. 판단 평가가 전역 자원 상태를 직접 참조하는 부분도 있다(`1879` 이후).
- 권한위임은 `2861`에서 상급 노드의 순간 대기열을 직접 확인한 후 즉시 발생한다. 위임의 전달, 범위, 만료, 회수는 별도 상태로 충분히 표현되지 않는다. 승인 노드 부재도 `2854`에서 승인 완료로 처리된다.
- ICC가 재배정한 새 명령(`2756` 이후)이 원래 상급 `d.commander`로 생성되어 발령자도 상급으로 기록된다(`js/model/iads/c2-agent.js:18`). 원 명령과의 계보도 없다. 누가 판단·발령했는지의 감사에는 한계가 있다.

따라서 지연된 상황인식, 식별 불확실성, 통신 단절 중 권한의 정당성, 회복 후 상태 정합성을 이 모델로 입증하기 어렵다. 해당 절차를 연구 질문으로 삼으려면 우선 명시적인 모델 요구사항과 검증 기준이 필요하다.

### 7. [P2 / 모델 가정] 개별 처리시간을 실제 인간 결심시간으로 읽기 어렵다

기본 `floor=0`에서 `js/engine/sim-engine.js:965`는 체계·운용자 합산 평균을 지수분포 한 번으로 추첨한다. 실제 기본 실행에서 KAMDOC의 항적 처리 0.187초, MCRC 0.364초, To-Be IAOC 0.126초 사례가 확인됐다.

지수분포는 대기행렬 개념모형에서 사용할 수 있으므로 곧바로 구현 오류라고 할 수 없다. 하지만 개별 전문의 이동과 인간 판단을 보여 주는 화면에서는 그 짧은 시간을 현실 절차로 오인할 수 있다. `floor=1`도 체계 성분 하한을 추가할 뿐 인간 판단의 최솟값을 보장하지 않는다. 평균을 맞추는 것과 분포·작업 내용을 검증하는 것은 다르다.

### 8. [검증 방법론] 기대 결론을 정상 동작의 필수조건으로 고정해서는 안 된다

`README.md:270`은 ‘As-Is 핵심 병목=교전 협조’, ‘To-Be 병목=무기체계로 이동’ 등을 모든 변경 후 유지해야 한다고 적는다. 장부 보존이나 명시된 능력 제약과 달리 이런 병목 결론은 입력과 근거 개선에 따라 반증될 수 있는 가설이다.

이는 **문서에 있는 검증 규칙의 문제**다. 모든 구현이 의도적으로 결론에 맞춰졌다는 증거로 해석하지 않는다. 반증 실험, 개념값 공개, 불리한 결과 기록 등 저장소의 좋은 관행도 함께 확인했다.

`seed29`의 대표성 근거는 9월 3일 당시 조건에서 선정된 예시다(ADR-084). 이후 발사점·표적·결심시간 기본값이 변경되었으므로 현재 조건 전체의 대표성이나 평균 성능을 뜻하지 않는다. 같은 seed의 1회 전환은 설명용 재생에 유용하지만 효과 추정을 대신하지 않는다. 현재 단일본의 정확한 적용 설정을 고정한 반복 비교와 불확실성 보고가 필요하다.

## 잘 구현된 부분

- 단일본이 현재 소스와 일치하며 자체 완결성·적재 순서 검사를 통과했다.
- `flowTrace`는 노드 도착·처리 개시·완료·이탈과 채널 대기·드롭을 기록한다. 관측을 켜도 동역학이 달라지지 않는지와 노드 장부 대사를 검증한다.
- 보고, 교전현황, 협조 채널을 구분하고 병렬 계통을 별도 레인으로 보여 주는 설계가 있다.
- 명령 생성·송신·접수·활성·만료·취소·결과를 추적하는 수명주기가 있다.
- 센서 물리·교전 가능 상태 대기와 지휘 처리 지연을 구분하려는 설계, 파라미터 근거 등급 및 ADR 기록이 있다.
- 지상배치 방공 C2라는 연구 범위를 명시했다. 해상·항공 전력을 제외한 것 자체를 구현 결함으로 보지 않는다.

## 실행한 검증과 범위

전체 테스트를 실행한 것은 아니며, 관련된 9개 스위트를 선정했다.

| 스위트 | 결과 |
|---|---|

| flow-trace | 통과 |
| approval-chain | 통과 |
| approval-pipeline-realism | 통과 |

| c2-echelon-hierarchy | 실패 3건 |

실패 3건은 KAMDOC 드롭 발생 기대와 As-Is 결과·제대 도착 수 고정값이다. 실제 해당 시험에서 KAMDOC 드롭은 0건이었다. 기준값 불일치가 확인되었지만, 이번 검토만으로 각 불일치의 변경 원인을 확정하지 않는다. 기대값만 바꾸어 통과시킬 근거도 없다.

별도로 저장된 단일본 코드의 기본값/명시값 실행, 신규 작업 포화, 상태정보 노후·역순 도착, 상세 기록 절삭을 확인했다. 시험 로그와 원시 수치는 이 디렉터리의 증거 파일에 보관했다. 반복 실행의 평균 효과, 실제 조직의 절차·시간과의 외부 대조, 브라우저 시각 QA는 수행하지 않았다.

## 사용 목적별 판단과 우선순위

| 사용 목적 | 현재 판단 |
|---|---|
| 보고·협조·명령 흐름 교육 및 토의 | 유용함. 개념화된 시간·권한을 구분해서 설명할 것 |
| C2 병목 가설 탐색 | 조건부 가능. 설정 불일치·실패 전파·상태정보·분모 문제를 먼저 다룰 것 |
| As-Is/To-Be 구조 효과의 정량 근거 | 현재는 불충분. 정확한 조건의 반복 비교 및 모델 타당성 근거 필요 |
| 실제 지휘 절차의 충실한 재현·적합성 판정 | 이 검토와 모델이 제공하는 근거 범위를 넘어섬 |

우선순위는 **실제 설정과 표시 일치 → 실패 범위 및 상태정보 정합성 → 전체·표본·미해결 계정 일치 → 정보·권한·환류의 모델 요구사항 검증 → 반복 비교와 외부 근거 대조**다.
