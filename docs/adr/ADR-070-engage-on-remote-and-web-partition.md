# ADR-070 — 원격 화력통제 교전(`engageOnRemote`) + 킬웹 웹 파티션 이식

> 본 문서의 모든 수치는 공개자료 기반 **정책연구용 개념값**이며 실제 작전자료가 아니다.

## 맥락

사용자 질문(2026-07-30): "현재 Air Defense에서는 As-Is 포대가 광역 센서를 못 쓴다고 되어 있는데
IADS에서는 어떻게 되어 있고, 원래 포대가 광역 센서를 활용해 요격하는 게 가능한지 팩트도 체크해줘."

### 팩트 체크 — 광역 감시 레이더로는 요격할 수 없다

이것은 모델의 편의가 아니라 **레이더 물리의 성질**이다. 요격에 필요한 것은 탐지(detect)가 아니라
**화력통제 품질 항적(fire-control quality track)** 이다.

| 등급 | 필요 정보 | 광역 감시 레이더(그린파인·FPS-117) | 포대 MFR(L-SAM/천궁/Patriot) |
|---|---|---|---|
| 탐지 | "저쪽에 뭔가 있다" | 가능 — 이것이 설계 목적 | 가능 |
| 추적 | 항적 번호·대략 진로 | 가능 | 가능 |
| **화력통제** | 요격 해를 계산할 수 있는 각도·거리 정밀도 + **갱신율** | **불가** | 가능 |

광역 레이더는 넓은 부피를 **긴 주기로** 훑도록 설계된다(그린파인 보고주기 16 s). 요격탄 유도에는
초 단위 갱신과 훨씬 좁은 각도 오차가 필요하다. 그래서 실제 체계에서도 조기경보 레이더는
"어디를 보라"를 알려주는 **큐잉(cueing)** 자산이고, 사격 해는 포대 MFR이 만든다.

**단, 다른 포대의 MFR 항적으로는 쏠 수 있다.** 이것이 IBCS류 통합 방공의 핵심 개념
**engage-on-remote**다 — 내 레이더에 안 잡혀도 옆 포대(또는 네트워크의 다른 FC급 센서)가 만든
화력통제 항적을 받아 내 발사대로 쏜다. 여기서 "원격"의 대상은 **광역 감시 레이더가 아니라 다른
포대의 화력통제 레이더**다.

### IADS_codex는 어떻게 하는가 — ADR-051 D2

codex ADR-051 D2가 정확히 위 구분을 코드로 규정한다: 킬웹 내 다른 자산이 확보한 화력통제 품질
항적으로 사격할 수 있고, **탐지 전용 자산(조기경보 레이더)은 자격을 주지 못한다.**
Air_Defense에는 이 경로가 없었다 — 포대는 오직 **자기 MFR**이 화력통제 등급을 잡을 때만 쐈다.

즉 As-Is/To-Be 양쪽에서 통합의 핵심 이득 하나가 모델에 빠져 있었다.

## 결정

### D2 — 원격 화력통제 교전(`engageOnRemote`)

`_iadsRemoteFcGrade(shooter, threat, t)`(`js/engine/sim-engine.js`)를 도입한다. 자기 MFR이
준비되지 않았을 때 다음을 **전부** 만족하는 원격 항적이 있으면 발사 자격을 준다:

1. `tr.state === FIRE_CONTROL` — 화력통제 등급 항적만
2. `KJ.IADS.trackFreshness(tr, t, 3).fresh` — 신선도 3초 이내
3. `KJ.IADS.hasFireControlCapability(spec, threat.type)` — **탐지 전용 자산 배제**(D2 핵심)
4. `_iadsWebOf(sensor) === _iadsWebOf(shooter)` — 웹 파티션 경계 안(D1, 아래)

To-Be(`mode === 'tobe'`) 전용이다 — 킬웹이 없는 As-Is에는 원격 항적을 통합할 네트워크 자체가
없다. 따라서 **As-Is 거동은 ON/OFF에서 bit-exact로 동일**하다(`tests/codex-alignment.test.mjs` §4가
세 시나리오 전부에서 어서션).

`_iadsFireControlState`가 `ready: ownReady || remote`, `state: remote ? 'FIRE_CONTROL_REMOTE' : state`로
바뀌고 `global.remoteFcGrants`를 계수한다.

### D1 — 킬웹 웹 파티션

D2만 넣으면 **킬웹이 전국 단일 평면**이 되어, 국지방공 포대가 상급 킬웹의 항적으로 쏘고
USFK 센서 항적까지 흘러든다. codex ADR-051 D1은 킬웹을 **웹(web) 단위로 분할**한다.
`_iadsWebOf(node)`:

```js
if (node.forceOwner === 'USFK') return 'usfk';                          // ADR-036 독립축
if (node.forceOwner === 'ROK_LOCAL_AD') return 'local_ad';              // 국지방공 웹
if (node.category === 'sensor' && node.localAdPosKey) return 'local_ad'; // 국지방공 소속 센서
return 'upper';                                                          // 상급 킬웹
```

원격 화력통제는 **같은 웹 안에서만** 성립한다. 결과:

- 국지방공 포대(3문)는 상급 킬웹 항적으로 쏘지 못한다 — 지휘관계가 다르다
- USFK 축은 자격 부여·수령 **양방향 모두** 차단(ADR-036)
- `local_ad` 센서 2기, 사수 3문 — `tests/codex-alignment.test.mjs` §5가 분류를 고정

사용자 지시(2026-07-30): "웹 파티션까지 이식한 뒤 기본 ON 판단해줘."

### 판정 — **기본 OFF, 단 사용자 노출 실험 옵션**

원격 교전은 **격추율을 유의하게 올리면서 비용 지표를 폭주시킨다.** 판정의 갈림길은
"그 폭주가 능력의 성질인가, 우리 WTA가 비용을 못 보는 탓인가"였고, `nativeWtaMode`(ADR-059
비용 인식 WTA)를 함께 켠 셀로 이를 분리했다.

**결과: 비용 인식 WTA는 폭주를 전혀 억제하지 못했다** — SC1·SC2에서 `eor`과 `eorwta`의
To-Be 수치가 **소수점까지 동일**하다(SC2 exchangeSat 619.53 = 619.53, 요격탄 289.49 = 289.49 M$).

더 나아가 paired 검정은 `nativeWtaMode`가 **세 시나리오 전부에서 To-Be 팔 거동을 전혀 바꾸지
않음**을 보여준다(아래 §paired 검정). 즉 이 측정은 원격 교전의 비용 행태를 판정해 주지 못한 채,
**우리 비용 인식 장치 자체가 To-Be에서 작동하지 않는다는 별개의 결함**을 드러냈다.

두 가지가 미해결이므로 기본값으로 올리지 않는다:
1. 비용 인식이 To-Be에서 작동하지 않는다 — 원격 교전을 켜면 **교리적으로 방어 불가능한 사격 행태**가
   기본 결과가 된다(SC2에서 무인기 8대에 요격탄 290 M$, 고가유도탄 보존율 0.01)
2. 그 행태가 능력의 성질인지 비용항 결함인지 **여전히 분리되지 않았다**

**후속 과제(신규)**: ADR-059 비용항이 To-Be WTA 경로에서 소비되는지 먼저 확인 → 누락이면 배선
수정 → 그 뒤 적용범위 확대 → 그 다음 이 판정을 재검토. 순서가 중요하다(§paired 검정 참조).

### 사용자 결정(2026-07-30) — 옵션으로 노출

사용자 지시: "자동교전(070)은 옵션으로 시뮬레이션 사용자가 on/off 할 수 있도록 하자. 오히려 원격
교전 유무에 따라 비용지표가 폭주하는 것을 보여주는 것도 유의미할 것 같아."

**그래서 반사실 전용에서 사용자 노출 옵션으로 바꿨다.** 기본값은 **꺼짐** 그대로다.

- 딥링크 `eor=1`, 화면 상단 「⚙️ 모델 조건 · 실험 옵션」의 「원격 교전」 체크박스
- 라우터 정규화 방향이 **기본 ON 여덟 개와 반대**다 — 명시적 `'1'`만 ON으로 읽는다
  (기본 ON 플래그는 명시적 `'0'`만 OFF로 읽는다). `tests/codex-alignment.test.mjs` §5가 고정.
- 접힌 영역 안에서 **기본 ON 여덟 개와 시각적으로 분리**한다 —
  「🧪 실험 옵션 (기본 꺼짐)」 안내문 + `checked` 속성 없음
- 실행 라벨에 `원격 교전 ON(실험)` 표기(`js/ui/sim-view.js`), 패널 캐시 키에 `eor` 포함

이 옵션의 교육적 용도는 **"능력을 넣으면 격추율은 오르지만 비용 인식이 없으면 비용이 폭주한다"**
는 대비를 직접 보여주는 것이다 — 통합 방공의 이득이 자동으로 공짜가 아니라는 점이다.

## 예측 실패 1건 (기록 의무)

웹 파티션을 넣기 전 나는 **파티션이 원격 교전 효과를 줄일 것**이라고 판단했다 — 경계를 세우면
쓸 수 있는 원격 항적이 줄어들기 때문이다. 그 판단의 근거는 **단일 seed 관측 1건**(SC3 231 → 223)이었다.

30 seed로 재보니 **틀렸다** — SC1 격추율 Δ가 +4.1 → **+5.6pp로 오히려 커졌다.**
파티션이 국지방공 포대의 무분별한 원격 사격을 막아 요격탄을 아끼고, 그 결과 상급 웹의 정식
교전에 자원이 남은 것으로 보인다(기전 확정은 아님 — 관측).

**교훈**: 단일 seed로 방향을 판단해서는 안 된다. 이 저장소에서 같은 실수를 두 번째로 했다
(ADR-067의 "센서 1초 비중" 설명도 계측으로 반증됨).

## 한계 — codex와 의도적으로 맞추지 않은 것 1건

**As-Is 가시성 모델.** codex는 As-Is에서 포대가 **자기 MFR만** 사격 후보 판단에 쓴다(광역 센서
그림은 상급 C2에만 올라가고 포대로 내려오지 않는다). Air_Defense는 As-Is에서도 상급 C2가 지명한
사수에게 명령을 하달하는 구조이므로, 후보 판단의 정보 원천이 codex와 다르다.

이 차이를 맞추지 않은 이유: Air_Defense의 As-Is는 **KJADS 문제 정의(음성 VTC 협조 의존)** 를
재현하는 것이 목적이고, 그 병목은 정보 가시성이 아니라 **승인·협조 절차 지연**이다. 가시성까지
codex와 맞추면 As-Is가 이중으로 불리해져 To-Be 개선폭이 부풀려진다. 불변 규칙 7(정본 우선)에 대한
두 번째 의도적 이탈이며(첫 번째는 ADR-067 `ifcn:1`) 사유를 여기에 기록한다.

### 임무 지표 — 그런데 SC3에서는 나빠지는 축도 있다

포화 시나리오만 paired로 떼어 보면 **개선이 일방적이지 않다**:

| SC3 Δ(To-Be−As-Is)의 변화 (`eor − base`) | 값 | 방향 |
|---|---|---|
| 격추율 | **+1.40pp** [0.61, 2.18] ★ | 개선 |
| **누수율** | **+0.98pp** [0.23, 1.73] ★ | **악화** |
| **교전지연** | **+5.29 s** [2.15, 8.42] ★ | **악화**(느려짐) |
| **구조적실패** | **+2.97** [0.91, 5.02] ★ | **악화** |
| 결심지연 | −4.72 s [−7.18, −2.26] ★ | 개선 |
| 요격탄 | +48.1 M$ ★ | 비용 증가 |

**격추율이 오르는데 누수율도 오른다** — SC3은 절단(censored) 위협이 있어 두 비율의 합이 1이 아니기
때문에 수학적으로 가능하다. 즉 원격 교전이 교전 기회를 늘려 격추도 늘리지만, 자원·채널을 더 오래
점유해 **일부 위협은 오히려 놓친다**. 교전지연 +5.3초와 구조적실패 +2.97이 같은 방향을 가리킨다.

이 관측은 §판정을 뒷받침한다 — 원격 교전은 "켜면 무조건 좋아지는 능력"이 아니다.

**SC1·SC2에서 미분리였던 격추율 Δ가 유의하게 바뀐다.** 특히 SC2(무인기 8대)는 To-Be 격추율이
61.0% → 81.8%로 오른다 — 무인기는 포대 MFR 탐지가 어려워 **자기 레이더만으로는 못 쏘던 표적을
원격 항적으로 쏘게 되는** 구조다. 원격 교전의 능력 이득이 가장 크게 나타나는 셀이다.

### 비율 함정 검증 — 폭주는 분자에서 온다 (ADR-062)

`exchangeSat = interceptSatM / killedThreatSatM`이므로 **분모가 줄어도 값이 커진다**(ADR-062
지표 함정 목록). 그 가능성을 배제하기 위해 To-Be 팔에서 분자·분모를 직접 분해했다(10 seed):

| To-Be | interceptSatM(분자) | killedThreatSatM(분모) | 비율 | 고가유도탄 절대 소모 |
|---|---|---|---|---|
| SC1 OFF | 1.14 | 0.057 | 20.0 | 221.6 M$ |
| SC1 ON | **58.08** (51×) | 0.082 (증가) | 708.3 | 250.4 M$ |
| SC2 OFF | 38.40 | 0.355 | 108.2 | 32.0 M$ |
| SC2 ON | **287.78** (7.5×) | 0.476 (증가) | 604.6 | **284.8 M$** (8.9×) |
| SC3 OFF | 332.44 | 66.86 | 5.0 | 384.0 M$ |
| SC3 ON | 485.02 (1.5×) | 65.38 | 7.4 | 359.2 M$ |

**분모는 오히려 늘었다**(더 많이 격추하므로). 폭주는 전적으로 **분자 — 저가 포화위협에 쏟는
요격탄 비용**에서 온다. 고가유도탄 절대 소모도 SC2에서 8.9배 늘었으므로 **비율 지표의 함정이
아니라 실제 자원 소모**다. 확인 스크립트: 시나리오별 `interceptSatM`/`killedThreatSatM` 직접 집계.

### paired 검정 — 비용 인식 WTA는 **소수점까지** 무효다

seed별로 짝지은 Δ(To-Be−As-Is)의 변화(30 seed). `eor`과 `eorwta`를 나란히 둔다:

| 지표 | SC1 `eor` | SC1 `eorwta` | SC2 `eor` | SC2 `eorwta` |
|---|---|---|---|---|
| 격추율 | +5.73pp [3.83,7.62] ★ | +5.62pp [3.70,7.55] ★ | +20.78pp [18.60,22.96] ★ | +20.78pp [18.60,22.96] ★ |
| **exchangeSat** | **+701.0671** [647.10,755.03] ★ | **+701.0671** [647.10,755.03] ★ | **+516.7951** [499.85,533.74] ★ | **+516.7951** [499.85,533.74] ★ |
| 요격탄(M$) | +41.45 [32.61,50.28] ★ | +42.68 [33.64,51.72] ★ | +254.09 [243.36,264.83] ★ | +254.09 [243.36,264.83] ★ |
| 결심지연(s) | −19.30 [−25.07,−13.53] ★ | −19.17 [−24.89,−13.45] ★ | −198.92 [−213.33,−184.50] ★ | −198.92 [−213.33,−184.50] ★ |
| 격추수 | +3.80 ★ | +3.73 ★ | +12.03 ★ | +12.03 ★ |

**`exchangeSat`의 paired 평균이 소수 4자리까지 동일하다**(SC1 701.0671 · SC2 516.7951) —
`nativeWtaMode`를 켜도 To-Be의 저가위협 요격 비용 행태가 **단 한 seed도** 바뀌지 않았다는 뜻이다.
SC2는 전 지표가 동일하고, SC1만 As-Is 팔에 WTA가 적용되어 격추율·요격탄이 미세하게 다르다.

**SC3에서 To-Be 팔을 직접 떼어 보면 더 강한 결과가 나온다:**

| SC3 **To-Be 팔** (paired, `− base`) | `eor` | `eorwta` |
|---|---|---|
| 격추율 | +1.40pp [0.61, 2.18] ★ | **+1.40pp** (동일) |
| exchangeSat | +2.5963 [2.37, 2.82] ★ | **+2.5963** (동일) |
| 요격탄(M$) | +48.0867 [38.82, 57.35] ★ | **+48.0867** (동일) |
| 격추수 | +4.9667 [2.15, 7.78] ★ | **+4.9667** (동일) |

**탄도탄이 있는 SC3에서도 To-Be 팔은 소수 4자리까지 완전히 동일하다.** 세 시나리오 Δ 표에서
`eorwta`가 조금 다르게 보이는 것은 **전부 As-Is 팔이 움직인 탓**이다(`nativeWtaMode`는 양 모드에
적용되고, As-Is 쪽에서는 실제로 거동을 바꾼다).

### ⚠️ 진단 정정 — 원인은 "탄도탄 전용"보다 넓다

처음 나는 억제 실패의 원인을 "ADR-059 비용항이 탄도탄 전용이라 무인기에 발화하지 않는다"로
적었다. **SC3(탄도탄 다수) To-Be 팔도 bit 단위로 동일한 것은 그 설명으로 부족하다** — 탄도탄이
있는데도 비용항이 To-Be 거동을 전혀 바꾸지 못했다면, 위협 종류 문제가 아니라 **To-Be WTA 경로가
`nativeWtaMode`의 비용항을 소비하지 않는 것**일 가능성이 있다.

확정된 사실만 정리하면:
1. `nativeWtaMode`는 **세 시나리오 전부에서 To-Be 팔 거동을 전혀 바꾸지 않는다**(측정)
2. 따라서 **원격 교전의 비용 폭주를 억제할 수 없다**(측정) — 이것이 §판정의 근거로 충분하다
3. 왜 To-Be 팔이 불변인지는 **미확정** — 위협 종류 한정인지 소비 경로 누락인지 분리해야 한다

**후속 과제(수정)**: ADR-059 비용항이 To-Be WTA 경로에서 실제로 소비되는지 코드·계측으로 먼저
확인하고, 누락이면 배선을 고친 뒤 적용범위(무인기·항공기)를 확대한다. 순서를 뒤집으면 안 된다 —
소비되지 않는 항의 적용범위를 넓혀도 아무 일도 일어나지 않는다.

원자료: 스크래치 `paired075-sc{1,2,3}.txt`.

### As-Is 불변 확인

As-Is 팔 수치는 `base`와 `eor` 열에서 **완전히 동일**하다(SC1 76.8%/29.83/333.81/146.1 ·
SC2 61.0%/99.74/34.44/425.7 · SC3 41.7%/4.87/624.73/153.2). `engageOnRemote`는 킬웹 전용이므로
설계상 그래야 하고, `tests/codex-alignment.test.mjs` §4가 세 시나리오에서 bit-identical을 어서션한다.

## 검증

- `tests/codex-alignment.test.mjs` §4 — 원격 자격 부여 계수 > 0, **As-Is가 세 시나리오에서
  ON/OFF bit-identical**
- `tests/codex-alignment.test.mjs` §5 — 웹 분류(국지방공 사수 3문·센서 2기), D2 탐지 전용 배제
- `engageOnRemote` 기본 OFF이므로 `tests/hires-baseline.json` 지문은 이 변경에 영향받지 않는다

## 되돌리는 법

`engageOnRemote`는 기본 OFF이므로 되돌릴 것이 없다. 반대로 켜려면
`scripts/experiment-run.mjs --features '{"engageOnRemote":true}'`.
웹 파티션(`_iadsWebOf`)은 `engageOnRemote`의 유일한 소비처이므로 OFF 상태에서 거동에 영향이 없다.
