# ADR-078 — IAOC를 MCRC·KAMDOC의 상위 제대로 세운다 (대체가 아니라 계층)

- 상태: 채택
- 일자: 2026-08-01
- 관련: ADR-051(군단 AOC C2A) · ADR-056(To-Be 교전상태 통합) · ADR-058(승인 계선) · ADR-077(교전승인 조율층 이관)

## 배경 — 그림이 코드보다 앞서 있었다

ADR-077 직후 전체 노드 관계를 실측 점검하다 발견했다. To-Be에서 **MCRC·KAMDOC의 도착 건수가 0**이었다.

```
As-Is   KAMDOC 145 (ρ0.967) · MCRC 152 (ρ0.798) · 군단 AOC 58+37
To-Be   KAMDOC   0          · MCRC   0          · IAOC 231 · 군단 AOC 58+37
        └ IAOC의 항적 205 = As-Is의 145(KAMDOC) + 60(MCRC) — 정확히 흡수
```

원인은 `_resolveIadsCommanders`의 To-Be 분기가 한 줄이었기 때문이다:

```js
if (this.mode === 'tobe') {
  add(c2ByType('IAOC'), 'global', korean, 'KILL_WEB');   // IAOC 하나가 전부
} else {
  var root = c2ByType(category === 'ballistic' ? 'KAMD_OPS' : 'MCRC');
```

즉 모델의 IAOC는 **조율층이 아니라 두 체계의 대체품**이었다. 여기에 어댑터가 모든 센서를 IAOC로 직결시켜, 카탈로그에 존재하는 `MCRC → IAOC` · `KAMDOC → IAOC` report 계선은 **메시지 0건**이었다 — 2단계 경로가 1단계 직결에 최단경로 경쟁에서 항상 지기 때문이다.

문제는 [C2 구조] 탭이 `linksInMode`를 그대로 그린다는 점이다. **화면에는 체계층 → 조율층 계선이 그려져 있는데 엔진은 그 선을 한 번도 쓰지 않았다.** 그 그림과 함께 수치를 제시하면, 존재하지 않는 구조에서 결과가 나온 것처럼 읽힌다.

교리적으로도 틀렸다. 통합의 요체는 기존 체계 위에 조율층이 **얹히는** 것이지 기존 체계가 **사라지는** 것이 아니다.

## 결정

IAOC를 MCRC·KAMDOC의 상위 제대로 세운다. 역할 분담은 사용자가 제시한 정의를 따른다.

| 제대 | 역할 |
|---|---|
| **IAOC** (조율층) | plot 처리 · 항적 표준화 · 교전정보 관리(표적할당 · 우선순위 · 발사 · 격추 · 자산 잔량 통합) |
| **MCRC** (공중 도메인) | 공군 관제레이더 · plot 융합 · 우군기/민항기 식별 |
| **KAMDOC** (BMD 도메인) | 그린파인 · 패트리엇 · 천궁-II · L-SAM 통제 |
| **ADC2A** (국지 도메인) | 군단·수방사 국지방공 — 종전과 동일 |

### 핵심 설계 — 직렬 중계가 아니라 **병렬 통보**

센서 항적은 조율층으로 **직결**되고, 도메인 제대는 **같은 시각에 같은 항적을 함께 받아** 자기 도메인 처리를 한다. 제대 처리는 조율층의 결심을 gate하지 않는다.

```
센서 ──────────────────────────▶ IAOC  (결심: 표적할당·우선순위)
  └──(같은 시각 병렬 통보)────▶ MCRC 또는 KAMDOC  (도메인 처리)
```

도메인 분담은 As-Is 책임 분담과 같다 — 공중(ABT)은 MCRC, 탄도는 KAMDOC.

### 두 제대의 C2 흐름은 대칭이다

다루는 **위협과 자산**은 다르지만 **C2 관점의 흐름은 같아야 한다**. 실측 확인:

```
MCRC   : ←ICC(coord) · ←도메인감시레이더(report) · ←조율층(coord) · →ICC(coord) · →조율층(coord) · →조율층(report)
KAMDOC : ←ICC(coord) · ←도메인감시레이더(report) · ←조율층(coord) · →ICC(coord) · →조율층(coord) · →조율층(report)
```

관계의 **종류**가 완전히 같다. 다른 것은 자산뿐이다 — 도메인 감시레이더 개수(MCRC 2대: ACR_E·ACR_W / KAMDOC 1대: 그린파인)와 처리 용량(MCRC 8서버 / KAMDOC 3서버). 엔진 쪽도 대칭이다: 병렬 통보가 두 제대에 같은 job kind(`iads_track`)로 들어가고 어느 쪽도 특별 취급이 없다. `c2-echelon-hierarchy.test.mjs` #7이 이 대칭을 잠근다 — 한쪽에만 관계가 생기면 실패한다.

**직렬 중계로 먼저 구현했다가 되돌렸다.** 두 가지 부작용이 실측으로 드러났다:
1. 제대 처리시간이 결심 경로에 얹혀 조율층 타임라인이 제대 용량에 종속된다 — 킬웹 전제(IFCN이 융합 항적을 일괄 배포)와 어긋난다.
2. 도메인 레이더 경로가 2단계가 되어 최단경로 경쟁에서 지고, **그 레이더의 기여가 통째로 사라진다**. 그린파인 항적을 KAMDOC 경유로 바꾸자 포대 전속 MFR(1단계)이 항상 이겨 KAMDOC 처리가 0이 됐다 — 통합 구조인데 정보가 줄어드는 역설.

병렬 통보는 두 문제를 동시에 없앤다. 사용자 표현으로 "거치되 시간은 그대로"다.

### 함께 바로잡은 배선

- **군단 AOC 교전현황 수신처**: MCRC → **IAOC**. 종전에는 도착 0건인 MCRC 앞으로 보내고 IAOC가 꺼내 읽는 모양이었다(ADR-056이 "수신자가 MCRC 역할 노드이지 책임 C2가 아님"이라 적고 소비 축을 넓혀 우회한 흔적). 이제 수신처가 책임 C2와 일치해 그 우회가 불필요해졌다(폴백은 무력화 배치용 안전망으로만 남긴다).
- **As-Is 음성 협조 직결선**(`군단 AOC ↔ MCRC` status/report/승인coord): **As-Is 전용**으로 제한(`comm.tobe = null`). 종전에는 같은 선의 To-Be 지연만 2초로 바꿔 두어 **경로는 그대로 두고 속도만** 빨라졌다. 그래서 To-Be 그림에 옛 직결선과 IAOC 허브가 동시에 그려져 무엇이 달라졌는지 대비되지 않았다.
- **상행 협조 계선**: `모든 C2 → IAOC` coord 추가. 계선을 반쪽만 두면 다음에 조용히 `responsibility_gap`이 난다.

## 결과 — 실측 (SC3 · ×1.5 · seed 12345 · 900초 · HANBANDO_LEGACY_NORMAL)

| 노드 | As-Is | To-Be (종전) | To-Be (ADR-078) |
|---|---|---|---|
| MCRC | 152 · ρ0.798 | **0** | **60 · ρ0.294** |
| KAMDOC | 145 · ρ0.967 · 드롭 23 | **0** | **145 · ρ0.969 · 드롭 18** |
| IAOC | — | 231 · ρ0.032 | 231 · ρ0.036 · Wq 0 · 드롭 0 |
| 군단 AOC | 58 · 37 | 58 · 37 | 58 · 37 |
| 교전현황 발신/도달/드롭 | 60 / 4 / 49 | 51 / 51 / 0 (→MCRC) | **70 / 70 / 0 (→IAOC)** |
| 격추 | **64** | 117 | **114** |

도메인 분담 실측: MCRC가 `uav_small 37 · fighter 18 · cruise 5`, KAMDOC이 `mrl_large 84 · srbm 61`. 공중/탄도가 정확히 갈린다.

### 기준선 이동

아홉 번째 재기준선이다(ADR-061 이관 → 065 → 066 → 067 → 068 → 072 → 076 → 077 → 078).

| 케이스 | 지문 | 격추 |
|---|---|---|
| sc1·sc2·sc3 **As-Is** | **전부 bit-exact 불변** | 22 · 13 · 64 |
| sc1\|tobe | 변경 | 23 → **25** |
| sc2\|tobe | 변경 | 13 (동일) |
| sc3\|tobe | 변경 | 117 → **114** |

As-Is 3케이스 불변이 변경 범위의 하드 체크다. `decision-audit`·`shadow-eval`·`engagement-state-unification`의 As-Is 지문도 전부 종전 값 그대로다.

## ⚠️ 주목할 결과 — 통합해도 BMD 제대 포화는 남는다

KAMDOC은 To-Be에서도 **ρ=0.969 · 드롭 18건**이다. 통합이 제대의 처리 용량을 늘려 주지는 않는다는 뜻이며, 이건 숨길 게 아니라 이 모델이 말할 수 있는 실질적 발견이다.

다만 그 드롭의 성격은 As-Is와 다르다. As-Is에서 KAMDOC 드롭은 **교전 기회 상실**이다(그가 책임 C2다). To-Be에서는 **상황인식 손실**이다 — 교전 계선은 조율층이 쥐고 있고 병렬 통보는 아무것도 gate하지 않으므로, 제대가 포화여도 교전은 진행된다. 이 차이가 격추 64 → 114의 상당 부분을 설명한다. 수치를 인용할 때 이 구분을 함께 밝혀야 한다.

## 하지 않은 것

**KAMDOC의 하행 사격통제 경유**(IAOC → KAMDOC → ECS)을 넣지 않았다. 구현해 보고 되돌렸다 — 엔진의 서비스시간은 **노드당 하나**라, 항적 처리용으로 교정된 KAMDOC 37.5초 × 3서버를 교전지시 중계에도 그대로 쓰게 된다. 실측하면 ρ=0.934 · 드롭 41이 되어 To-Be 격추가 117 → **26**으로 무너졌다. 이건 구조가 만든 결과가 아니라 **파라미터 오적용이 만든 인공물**이다(교전지시 중계에 37.5초를 쓸 근거가 없다).

제대로 하려면 job kind별 서비스시간과 그 근거값(params.md 신규 등록)이 필요하다. 현재 모델에서 KAMDOC의 포대 통제는 기존 `KAMDOC ↔ ICC` coord 계선으로 표현된다. 사유는 `_onIadsFire`에 주석으로 남겼다.

## 별건으로 발견한 것 — 그린파인이 SC3에서 항적을 0건 만든다

상급 C2가 받은 출처를 센서 유형별로 세면:

```
As-Is(KAMDOC): FPS117 51 · MSAM_MFR 82 · PATRIOT_RADAR 6 · TPS880K 6     ← GREEN_PINE 0
To-Be(IAOC)  : FPS117 74 · MSAM_MFR 121 · PATRIOT_RADAR 8 · LSAM_MFR 8 · TPS880K 16
```

KAMDOC의 As-Is 부하 145건은 그린파인이 아니라 포대 전속 MFR에서 온다. 섞어쏘기 시나리오에서 **BMD 전용 장거리 감시레이더가 SRBM을 한 번도 탐지하지 않는 것**은 그 자체로 의심스럽다. 센서 모델(탐지 기하·RCS·SNR) 문제라 이번 범위 밖이며, 별도 과제로 남긴다.

## 부수 작업 — 「홉」 용어 폐기

「홉(hop)」은 네트워크 용어라 보고서 독자에게 통하지 않는다. 저장소 전체(시뮬레이터 UI · 모의논리서 · 실험보고서 · ADR · params.md · 코드 주석 · 테스트)에서 **「경유」**로 통일했다 — 26개 파일 99건.

- `승인 홉` → `승인 단계` · `협조 홉` → `협조 단계` · `1홉/2홉` → `1단계/2단계`
- `아홉`(숫자 9)은 보호했다(3건) — 기계 치환이 「아 경유」를 만들 뻔했다.


## 후속 결정 — EOC 노드 삭제 (교전 운영을 IAOC로 흡수)

위 검토에서 **EOC(교전운영센터)가 도착 0건**임이 드러났다. 선언되고, 링크가 깔리고, [C2 구조] 탭에 그려지는데 실행에서는 아무 일도 하지 않았다 — 조율층에 IAOC와 나란히 놓여 있어 "두 노드가 역할을 나눠 맡는다"고 읽히지만 사실이 아니었다.

사용자 결정에 따라 **교전 운영(표적할당 · 우선순위 · 발사 · 격추 · 자산 잔량 통합)을 IAOC의 기능으로 흡수하고 EOC 노드를 삭제**했다. 조율층은 이제 IAOC 하나다.

| | 삭제 전 | 삭제 후 |
|---|---|---|
| To-Be 노드 | 66 | **65** |
| To-Be 링크 | 224 | **221** (EOC↔IAOC 3개) |
| As-Is 노드·링크 | 64 / 116 | **불변** |
| 격추·누수 (6케이스) | — | **전부 완전 동일** |

지문은 To-Be 3케이스만 바뀐다. 결과 wire shape(`r.nodes`)에서 EOC 항목이 빠진 것뿐이며, **격추·누수가 한 건도 안 움직인 것이 "아무 일도 안 하던 노드를 지웠다"는 정확한 서명**이다. As-Is 지문은 bit-exact 불변.

삭제 범위: `deployments.js`(선언 2곳 · 좌표 2곳) · `system-types.js`(C2 유형) · `deployment-adapter.js`(모드 판정) · `panels.js`(계층 정의 · 라벨 · 안내문) · `index.html`(탭 설명) · `decision-comparison.test.mjs`(조율층 정의 어서션).
