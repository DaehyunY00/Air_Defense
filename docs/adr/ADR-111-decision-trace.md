# ADR-111 — 결심 기록(trace.decisions): 「어떤 포대를 검토해 무엇이 가능했고 누구를 골랐는가」를 화면에

> 본 문서의 모든 수치는 공개자료 기반 **정책연구용 개념값**이며 실제 작전자료가 아니다.

- 날짜: 2026-10-02
- 상태: 채택 (관측 전용 — 플래그 없음 · `trace:true`일 때만 기록 · 동역학 bit-exact)
- 관련: ADR-073(결심 감사 로깅 — 분석 채널 전용이라 화면이 읽지 않음) · ADR-104(사전대기 큐·긴급발사 ②) · ADR-109/110(조기 사수 지정·되먹임)

## 맥락

지휘 흐름 화면의 항적 개별 보기는 **전문 하나하나**를 점으로 그린다. 그런데 「결심 지휘소가 예하 포대 중 어느 포대가 쏠 수 있는지 가리는」
과정은 엔진에서 **전문 없는 내부 계산**이다(C2가 포대 상태를 지연 없이 안다는 가정). 그래서 화면에는 결과(사수선정 마크)만 남고 과정이
없었다. 기록 패널의 「후보 검토」 행도 탈락 사유별 **최초 1건**뿐이었다. 사용자 검토(2026-10-02): "C2 관점에서는 각 포대 중 어떤 포대가
가능한지 확인하는 과정이 있어야 한다. 그 확인은 사실상 C2 관점의 교신이다 — 가능 포대 확인 + 어떤 포대가 쏠지 결심, 이것을 보이게 하라."

긴급발사 ②(ADR-104)는 더 심하다 — 큐를 받은 포대가 **스스로** 판단해 쏘고 C2는 결과만 안다. "8곳 중 1곳만 가능했다"는 사실이 어디에도
없었다.

## 결정

엔진 trace에 `decisions` 배열을 싣는다(위협당). 항목: `{ t, tEnd, n, kind:'formal'|'standby', c2, chosen, cands:[{ id, ok, why?, rank?, score?,
predicted?, readyAt? }] }`.

- **formal** — `_iadsDecide`의 후보 평가 루프(조기 사수 지정 ON이면 예측 평가). 포대마다 가능(ok)·탈락 사유(why = 엔진 사유 코드)·가능 후보의
  점수·순위. `chosen` = 점수 1위(이후 경로 부재·한미 협조 대기·승인 계선으로 실제 지정이 미뤄질 수 있다 — 그것은 기존 마크가 보여 준다).
- **standby** — `_tryIadsStandbyFire`의 큐 포대 자체 판단. 사유에 엔진 코드 외 `coalition_hold`(협조 대기·양보) · `outside_window`(요격 창 밖) ·
  `preempted`(먼저 쏜 포대가 있어 미평가)를 더한다. 발사한 포대가 `chosen`.
- **접기** — 같은 (kind, C2)에서 같은 판정표가 이어지면 새 항목 대신 직전 항목의 `n`·`tEnd`만 올린다(정식 결심은 1초 재시도, 큐 판단은
  센서 스캔마다 돈다 — 접지 않으면 SC3 FULL 1800초에서 35,547건·45 MB, 접으면 1,866건·+2 MB). 같은 시각의 재평가(큐 도착이 같은 초에
  겹칠 때)는 마지막 판정표로 덮는다. 항적당 상한 400(초과 시 `decisionsTruncated`).
- **순수성** — 난수·스케줄·분기를 건드리지 않는다. `trace:false`면 아무것도 만들지 않는다. 비교용 서명은 비열거 속성이라 JSON에 실리지 않는다.

## 화면(지휘 흐름)

- **이벤트 로그·기록 패널**: 「후보 검토 — KAMD_OPS · 가능 1/8 → L-SAM (LSAM_MID_NORTH) 선정 · 큐 포대 자체 판단」 한 줄 + 포대 명단(✓ 가능 #순위 ·
  ✗ 사유별 묶음). 반복은 「같은 판정 14회(~00:33.4)」로 접는다. 보라색(`.ev.review`).
- **그래프(항적 개별)**: 지금 시각에 살아 있는(t ≤ simT ≤ tEnd+3) 가장 최근 결심의 검토 포대에 고리를 씌우고 C2에서 점선을 잇는다. 보라 점선 =
  가능, 회색 = 탈락(위에 사유), 실선 = 선정. **전문이 아니라서 흐르는 점이 없다** — 범례에 「상태 그림 위의 계산 · 전문 없음」을 명시한다.

## 한계

- 이 기록은 C2가 포대 상태를 **지연 0으로 정확히** 안다는 기존 가정을 그대로 보여 준다. 상태 보고 지연(음성/데이터링크)을 모델에 넣는 것은 별도
  결정이며(그때는 이 기록의 "C2가 본 상태"와 "실제 상태"가 갈라진다), 이 ADR은 보이게만 한다.
- `chosen`은 점수 1위이지 최종 지정이 아니다. 최종 지정은 `사수선정·표적할당` 마크다.
