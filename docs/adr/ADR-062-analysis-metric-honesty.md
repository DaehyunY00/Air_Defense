# ADR-062 — 분석 탭 지표 정직성: 死 지표 제거·"미측정" 표기·승인 계선 토글

> 본 문서의 모든 수치는 공개자료 기반 **정책연구용 개념값**이며 실제 작전자료가 아니다.

## 맥락

분석 탭 지표 30종을 배치 2종 × 시나리오 3종 × 모드 2종 = **12셀 실측**한 결과, 전 셀에서
0인 지표가 5종 나왔다(원자료: 실측 스크립트 `probe-zero-metrics`, ×1.5·600초·seed 12345).
성격이 전혀 다른 두 부류였다.

| 지표 | 전 셀 값 | 성격 |
|---|---|---|
| ⑧ 무기 최대 평균대기 (Wq) | 0 | **native에 대응 관측량 자체가 없음** |
| ⑥⑦ 그중 협조 홉 지연 | 0 | 승인 계선(ADR-058) OFF라 미측정 |
| ⑥⑦ 승인 노드 최대 ρ | 0 | 〃 |
| ⑥⑦ 승인 대기 (Wq) | 0 | 〃 |
| ⑥⑦ 분권 전환 (횟수) | 0 | 〃 |

**핵심 문제**: 두 부류 모두 화면에는 똑같이 `0`으로 나오는데, 의미가 정반대다. 특히 후자는
0이 "승인 지연 없음 = 승인 병목 없음"으로 읽혀 이 연구의 핵심 결론 **G6① (As-Is 병목 =
협조·승인)과 정면으로 어긋나는 인상**을 준다. 게다가 UI는 `approvalChain`을 켤 수단이
없었으므로(ADR-061 이후 `modelConfig()`가 `highResolutionDeployment`만 전달) 화면에서는
**영구히 0**이었다 — 사용자가 스스로 확인할 방법조차 없었다.

## 결정

### 1. ⑧ '무기 최대 평균대기 (Wq)' 제거

native 교전 모델에는 **사수 대기행렬이 존재하지 않는다**. 동시교전 슬롯이 모두 점유되면
대기가 아니라 즉시 차단(`capacity_full`)되고 1초 뒤 재시도한다(`_iadsEvaluate`). 같은 카드의
ρ·차단수는 `iadsResources`(`activeTime`/`capacityBlocks`)에서 나오는데, Wq만 native가 한 번도
채우지 않는 `nodeState` 큐(`waitAccum`/`waitCount`)를 읽어 항상 0이었다.

실측: 사수 차단 999건(LEGACY·SC3)·3110건(To-Be) 셀에서도 Wq = 0.00. 툴팁은 "ρ와 달리 포화의
체감 비용을 직접 표현한다"고 적혀 있었는데 **포화가 가장 심한 곳에서 0**이었다 — 지표가
있으나 마나가 아니라, 있는 것이 해로웠다.

### 2. 같은 카드 '교전채널 포화 드롭 합' → '동시교전 슬롯 차단 (재시도)'

값의 실체는 `capacityBlocks`, 즉 **차단 후 재시도로 회복될 수 있는 사건**이다. "드롭(교전
기회 상실)"이라는 라벨·툴팁은 실제 의미보다 강해 상실을 과대표시했다. 실제 상실은
`overflow:<노드>`·`timeout` 실패코드로 따로 계상된다 — 툴팁에 이 구분을 명시했다.

### 3. ⑥⑦ 승인·협조 4종: 0 대신 "미측정 — 승인 계선(ADR-058) OFF"

지표를 삭제하지 않는다. `approvalChain` ON에서 전부 정상 발화하며, 그 값이 G6①의 직접
증거이기 때문이다(실측: 협조몫 20.1~36.6초 · 승인 ρ 0.18~0.44 · 승인 Wq 18~184초 ·
분권 전환 71~279회 — 부하의 함수). 대신 **측정하지 않은 값을 0으로 보여주지 않는다**:
`metricRow`에 `na` 경로를 추가해 값 4칸을 병합하고 사유를 표시한다.

판정 근거는 UI 상태가 아니라 **실행 결과가 스스로 신고한 `global.features.approvalChain`**
이다 — 화면 토글과 실제 실행 조건이 어긋나도 표기가 거짓말하지 않는다.

### 4. 승인 계선 토글 UI 노출 (`appr` 딥링크)

상단 컨트롤에 체크박스(`#approval-chain-toggle`)를 두고, 라우터에 `appr=<0|1>`을 추가했다.
**기본값 OFF** — 불변 규칙 1(신규 거동은 플래그 뒤, OFF는 bit-exact)을 유지한다. 알 수 없는
`appr` 값은 OFF로 정규화한다.

## 검증

`tests/analysis-metric-honesty.test.mjs`(run-all 등록, 20 어서션):
① 포화 셀에서 사수 차단 발생하나 Wq=0 — 제거 근거를 실측으로 고정(되살리면 실패)
② 분석 탭 소스 잠금(死 지표 행 부재·새 라벨·na 배선)
③ OFF는 4종 전부 0 / ON은 실제 발화 / 고부하 ON은 분권 전환 발화
④ 라우터·컨트롤·3개 modelConfig·CSS 배선
⑤ **OFF bit-exact** — 토글 OFF 실행이 종전 기본 실행과 SHA-256 동일, ON은 다름(장식 아님).

## 한계 (정직 기록)

1. **기본값 OFF의 대가** — 기본 화면은 여전히 승인·협조가 "미측정"이다. 사용자가 토글을 켜야
   G6①의 증거를 볼 수 있다. 기본 ON 전환은 결과 수치를 바꾸므로(편향 귀속·bit-exact 원칙)
   별도 Phase의 판단 사안으로 남긴다.
2. **`분권 전환`은 ON에서도 저부하면 0** — 임계(대기열 ≥ 서버×4) 초과에서만 발동하는 부하의
   함수다. 이 경우의 0은 "미측정"이 아니라 진짜 관측값 0이며, 현재 표기는 둘을 구분하지
   않는다(승인 계선 ON이면 값 0으로 표시). 더 세분한 표기는 후속 과제.
3. **다른 조건부 0 지표는 손대지 않았다** — 예: `복수출처 항적융합`은 To-Be에서 구조적으로 0
   (융합 허브가 단일 항적을 만들므로), `교전현황 음성/VTC 드롭`도 To-Be 0이 정상이다. 이들은
   As-Is에서 값이 나오므로 "전 셀 0"이 아니었고, 0 자체가 의미 있는 관측이라 유지했다.

## 되돌리는 법

이 커밋 revert. 런타임에서는 토글 OFF가 종전 화면과 동일한 실행 조건이다(표시 문구만 다름).

## 결론 영향

G6 4종 **불변** — 본 변경은 실행 수치를 바꾸지 않는다(OFF bit-exact, SHA-256 확인). 오히려
①(As-Is 병목 = 협조·승인)을 화면에서 **확인 가능**하게 만든다: 종전에는 켤 수단이 없어 항상
0으로 보였다.
