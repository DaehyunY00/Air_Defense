이번 보고서의 기준

SC3만 다룹니다. 기본 비교는 난수 시작값 29, 위협 생성 강도 1배입니다. 모든 비교 조건에서 생성 = 격추 + 막지 못함을 확인했습니다. 결과는 앞쪽 7개 장에, 용어와 설정의 뜻은 뒤쪽 「분석 방법」에 나눠 실었습니다.

1. 무엇을 비교했나

SC3는 여러 종류의 위협이 함께 들어오는 시나리오입니다. 기본 배치(LEGACY)와 확대 배치(FULL) 각각에서 As-Is와 To-Be를 비교했습니다. 같은 난수 시작값을 쓴 두 구조에는 같은 항적을 생성했습니다.

비교 항목이번 보고서에 실은 범위
기준 비교2개 배치 × 2개 구조 = 4개 조건
조건 하나씩 바꾸기12개 조건(지휘 조건 9 + 시간 가정 3) × 2개 배치 × 2개 구조 = 48개 조건
반복 실행20개 난수 시작값 × 2개 배치 × 2개 구조 = 80개 조건

대상을 고정하는 방법

기존 SC3의 30분(1800초) 동안 생성되는 항적을 대상으로 삼았습니다. 이후에는 새 위협을 추가하지 않고, 이미 생성된 항적을 끝까지 추적했습니다. 자산·표적 경로·교전 및 지휘 처리 규칙은 유지하고, 생성 마감과 결과 확인 종료를 분리했습니다.

동일 조건의 두 구조는 같은 대상과 같은 종료 상한을 사용합니다. 이 상한은 생성된 항적들의 예정 비행 종료 시각 중 가장 늦은 시각입니다. 표의 결과는 중간 시점의 실적이 아니라 전체 대상의 최종 결과입니다.

기준 조건에서 유지한 설정

교전 협조, 교전현황 공유, 자위권 사격, 권역통제 중계 인가를 사용했습니다. 시나리오 가정인 여러 지상 목적지 배정과 탄도 위협 출발점 연장도 켠 상태입니다. 원격 교전, 포대통제의 추가 집행시간, 별도 명령 발령 작업은 기본 조건에서 사용하지 않았습니다. 조건별 비교에서는 정해진 설정 하나만 바꿨습니다.

이번 보고서에서 다루지 않는 것

  • 탄도 위협 출발점 연장과 여러 지상 목적지 배정의 켜기/끄기 비교는 뺐습니다. 위협의 경로를 정하는 시나리오 가정이어서, 모든 실행에 켠 상태로 똑같이 적용했습니다.
  • 처리시간 최솟값 적용과 협조의 세부 처리 절차 생략도 뺐습니다. 지휘 대안이 아니라 모의의 세부 가정을 바꾸는 설정이고, 차이가 작으면서 배치·구조마다 방향이 엇갈렸습니다.
  • 위협 생성 강도는 1배만 다룹니다. 1.5배~3배 결과는 싣지 않았습니다.
  • 조건을 바꿔도 막지 못한 항적 수와 발사 수가 하나도 달라지지 않은 조건은 표에서 뺐습니다.
두 종류의 비교를 구분합니다

As-Is와 To-Be는 같은 배치 안에서 비교합니다. LEGACY와 FULL은 자산 구성이 서로 다른 배치이므로, 둘의 차이를 지휘구조 변화 하나로 해석하지 않습니다.

막지 못한 항적격추되지 않은 채 모델의 비행 종료 지점까지 도달한 항적입니다. 한 발도 발사하지 못한 경우와 발사했지만 격추하지 못한 경우를 모두 포함합니다. 시뮬레이터 화면과 이전 문서에서는 「누수」라고 적습니다.

B. 목적지와 출발점 설정의 뜻

두 설정은 지휘 절차가 아니라, 위협이 어디서 출발해 어디로 향하는지를 정하는 시나리오 가정입니다. 이 보고서의 모든 실행은 두 기능을 켠 상태로 똑같이 진행했고, 켜기/끄기 비교는 분석에서 뺐습니다.

여러 지상 목적지 배정

등록된 여러 지상 목적지 중 하나를 위협에 배정하는 기능입니다. 끄면 해당 진입 방향에 정해진 기본 목적지 하나를 사용합니다. 목적지 주변으로 위치를 흩어 놓는 설정은 별도로 유지됩니다. 단거리 탄도탄과 대구경 방사포에 적용됩니다.

탄도 위협 출발점 연장

기존 진입 지점보다 더 먼 가상의 출발점에서 비행을 시작하게 하고, 늘어난 거리에 맞춰 비행시간도 늘리는 기능입니다. 끄면 기존 진입 지점부터 비행을 모의합니다.

C. 비슷해 보이는 분류의 차이

이름만으로 특정 지휘소의 잘못이나 실제 요격 성공 가능성을 단정하지 않습니다.

보고서 표현어떤 근거로 붙인 분류인가
후보 자산에서 요격 가능한 지점을 찾지 못함담당 지휘부가 후보로 삼은 범위에서, 비행 구간 전체의 시간·거리·고도 조건을 간단히 검사해도 가능한 지점이 없었던 경우입니다. 탄약·교전 채널·사격통제 정보가 정상이라는 가정 아래의 검사입니다.
발사 전 시간 종료(세부 원인 미분류)실제 발사 없이 항적의 비행이 끝났고, 다른 구체적인 주원인으로 분류되지 않은 경우입니다. 내부 코드 이름은 timeout:c2이지만 특정 C2 노드가 처리시간 제한을 넘었다는 직접 증거는 아닙니다.
요격 가능한 시기를 놓친 것으로 분류결심·명령 진행 시점과 교전 가능한 시간 등의 근거로, 요격할 수 있는 시기를 놓친 것으로 모델이 분류한 경우입니다. 내부 코드 이름은 window_lost_due_to_c2입니다.

둘 다 시간이 관련돼도 같은 뜻은 아닙니다

“발사 전 시간 종료”는 발사 전에 끝났다는 결과와 세부 원인 미분류를 뜻합니다. “요격 가능한 시기를 놓침”은 교전 기회와 처리 시점에 관한 근거를 추가로 사용한 분류입니다. 따라서 전자를 지휘 지연이 확인된 사건 수로 읽으면 안 됩니다.

분류만으로 알 수 없는 것

어느 MCRC·ICC·ECS에서 얼마나 지연됐는지는 해당 항적의 접수·처리·명령 전달 기록을 따로 확인해야 합니다. 지연이 없었으면 반드시 격추됐다는 뜻도 아닙니다. 마찬가지로 후보 검사에서 요격점을 찾지 못했다고 모든 보유 자산으로 요격이 불가능했다고 결론 내리지 않습니다.

최종 결과와 원인 설명의 수준을 구분합니다

막았는지 못 막았는지는 항적의 최종 결과입니다. 막지 못한 이유는 모델이 가진 기록과 판정 규칙으로 붙인 주된 설명입니다. 서로 다른 분류는 서로 다른 근거를 사용하며, 원인이 직접 확인된 정도까지 모두 같지는 않습니다.
