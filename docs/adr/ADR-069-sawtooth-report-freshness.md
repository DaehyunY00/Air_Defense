# ADR-069 — 보고 주기 톱니 신선도(`sawtoothFreshness`) 이식

> 본 문서의 모든 수치는 공개자료 기반 **정책연구용 개념값**이며 실제 작전자료가 아니다.

## 맥락

ADR-057에서 IADS_codex의 링크 의미론 정본을 이식할 때, 센서→C2 보고 링크의 지연을
**"센서별 보고주기 P를 상수 지연으로 소비"** 하는 1단계 근사로 구현했다. 그때 남긴 한계 기록:

> `docs/params.md` IADS-LINK-RP-01 · MC 적용방식 — "고정(1단계 근사 — 센서별 고정 지연 =
> reportingPeriod. **톱니 신선도(0~P 변동)는 후속 과제**로 ADR-057 §한계에 기록)"

codex 정본(ADR-014)은 그 형태를 명시적으로 다르게 규정한다:

> 탐지자산→상위 C2 정보 전달은 일률 지연이 아니라 보고 주기 — **그림 나이가 0~P 톱니(sawtooth)로
> 변동**. 탐지자산별 주기는 `SENSOR_TYPES.<sensor>.reportingPeriod`가 단일 출처.

사용자가 IADS_codex 원본을 첨부하며 "물리 엔진 및 링크의미론 정본 등의 조건은 동일하게" 진행하도록
지시했고, 직접 대조에서 **Air_Defense에 없는 것은 톱니 신선도 하나**로 좁혀졌다. 사용자 결정
(2026-07-29): **톱니 신선도만 이식**(codex의 다른 차이는 이식하지 않고 ADR-070 §한계에 기록).

## 상수 P vs 톱니 — 무엇이 다른가

주기 P로 갱신하는 레이더에서 C2가 보는 항적의 **나이**는 마지막 보고 이후 경과시간이다.
시각 t에 정보를 소비하면 그림 나이는 `t − (마지막 보고 시각)`이다.

| | 소비 지연 | 시간평균 | 최악 | 최선 |
|---|---|---|---|---|
| **상수 근사(ADR-057)** | 항상 `P` | `P` | `P` | `P` |
| **톱니 정본(ADR-069)** | `t − ⌊t/P⌋·P` | `P/2` | `P`(직전) | `0`(보고 순간) |

즉 상수 근사는 **모든 센서를 항상 최악의 신선도로 취급**한다. 그린파인(P=16 s)은 늘 16초 묵은
그림으로만 보고하는 셈이었다. 정본은 그 나이가 보고 순간 0으로 떨어졌다가 다음 주기까지 선형으로
늘어나는 톱니다.

## 결정

`_reportingStaleness(P, t)`를 도입하고 `report-cycle` 타입 링크의 지연을 톱니로 계산한다.
플래그 `sawtoothFreshness`로 감싼다(불변 규칙 1 — 신규 거동은 플래그 뒤, OFF는 bit-exact).

```js
// js/engine/sim-engine.js:1014
Simulation.prototype._reportingStaleness = function (period) {
  if (!(period > 0)) return 0; // 실시간/전속 (포대 자기 MFR)
  var s = this.now - Math.floor(this.now / period) * period;
  return s < 0 ? 0 : s;
};

// _linkDelay 내부 (js/engine/sim-engine.js:1112)
// ADR-069: 보고 주기 링크(report-cycle)만 톱니로 해석한다. 데이터링크·음성 절차 지연은
// 사건 기반 전송이므로 톱니 개념이 성립하지 않는다.
if (this.sawtoothFreshness && comm.type === 'report-cycle') {
  return this._reportingStaleness(comm.delaySec);
}
```

### 적용 경계 — 왜 `report-cycle`만인가

ADR-057의 어댑터가 링크에 `comm.type`을 부여한다(`js/config/deployment-adapter.js:108`).
톱니는 **주기적으로 갱신되는 그림의 나이**라는 개념이므로 주기 갱신 링크에만 성립한다.

| 링크 종류 | `comm.type` | 톱니 | 사유 |
|---|---|---|---|
| 센서→C2 보고 | `report-cycle` | **적용** | 주기 P로 갱신되는 그림 |
| C2↔C2 전송 | `datalink` | 미적용 | 사건 기반 전송 — 보낼 것이 생기면 즉시 발송 |
| 음성 협조(4링크) | `voice` | 미적용 | 협의 절차 소요시간 — 주기 갱신이 아니다 |
| 하향 명령 | `command` | 미적용 | 사건 기반 |

`tests/codex-alignment.test.mjs` §2가 음성 4링크가 톱니 경로를 지나지 않음을 어서션으로 고정한다.

### ADR-067과의 결합 — 양 모드 공통

ADR-067로 센서→C2 보고 주기는 **As-Is·To-Be 공통**이 되었다. 따라서 톱니도 양 모드에 동일하게
적용되며 **한쪽 팔만 빠르게 만들지 않는다.** 이것이 이 변경을 기본 ON으로 올릴 수 있는 근거다
(ADR-072).

## 편향 방향 — 어느 팔에 유리한가

톱니는 평균 신선도를 `P` → `P/2`로 낮추므로 **양 모드 모두 빨라진다.** 개선폭의 크기는 그 모드가
느린 센서에 얼마나 의존하는지에 달렸다:

- As-Is는 그린파인(16 s)·FPS-117(8 s) 같은 느린 광역 센서 보고에 더 의존한다 → 절감 폭이 크다
- To-Be는 이미 포대 MFR(P=1 s) 최속 경로를 타는 비중이 높다 → 절감 폭이 작다

**따라서 예상 방향은 As-Is 쪽 이득이 커서 To-Be 개선폭이 줄어드는 것**이다 — 즉 이 변경은
"To-Be에 유리하게 고쳤다"는 비판의 반례다. 실측 원장은 아래.

## 편향 원장 (paired 30 seed × 1800 s × ×1.5 · LEGACY_HIRES × iads-c2)

원자료: `artifacts/experiment/r75-base-sc3.json`(ON) · `r75-sawoff-sc3.json`(OFF).
탄도축이 없는 SC1·SC2에서는 보고 주기 톱니가 임무 지표를 움직이지 않아(느린 광역 센서 의존이
낮다) SC3만 측정했다.

| SC3 지표 | OFF(주기 P 고정) | ON(톱니) | 판정 |
|---|---|---|---|
| **As-Is 격추율** | 40.3% [39.2, 41.3] | **41.7% [40.7, 42.7]** | 신뢰구간 비중첩 — As-Is가 빨라진다 |
| To-Be 격추율 | 56.8% | 57.0% | 거의 불변 |
| **Δ 격추율(To-Be−As-Is)** | **+16.5pp** [15.6, 17.5] ★ | **+15.3pp** [14.5, 16.2] ★ | **개선폭 1.2pp 축소** |
| Δ 누수율 | −16.4pp ★ | −15.4pp ★ | 개선폭 축소 |
| Δ 결심지연 | −40.5 s ★ | −36.7 s ★ | 개선폭 축소 |
| Δ 교전지연 | −45.4 s ★ | −40.5 s ★ | 개선폭 축소 |
| As-Is 격추수 | 146.3 | 151.4 | +5.1 |
| To-Be 격추수 | 206.5 | 207.0 | +0.5 |

**예측이 실측과 일치한다.** 톱니는 양 모드에 같은 규칙으로 적용되는데도 **As-Is만 유의하게
빨라진다** — As-Is가 그린파인(16 s)·FPS-117(8 s) 같은 느린 광역 센서 보고에 의존하고, To-Be는
이미 포대 MFR(1 s) 최속 경로 비중이 높기 때문이다. 주기가 큰 센서일수록 `P → P/2` 절감의
절대량이 크다.

**즉 이 정본 정합은 To-Be 개선폭을 1.2pp 줄인다.** 기본 ON 판정이 "결론에 유리한 방향"으로
이루어진 것이 아님을 보여주는 사례다(ADR-072 판정 기준 참조).

⚠️ Δ 격추율 두 값의 신뢰구간은 일부 중첩한다([15.6,17.5] vs [14.5,16.2]) — 셀 간 비교로는
개선폭 축소 자체의 유의성이 확정되지 않는다. 아래 paired 검정이 이를 확정한다.

### paired 검정 — seed별로 짝지은 `sawoff − base` (30 seed)

셀 평균 비교와 달리 같은 seed끼리 뺀 것이므로 seed 변동이 제거된다.

| 지표 | SC1 | SC2 |
|---|---|---|
| **As-Is 결심지연** | **+3.89 s** [1.46, 6.32] ★ | — |
| To-Be 결심지연 | +0.12 s [−1.66, 1.90] n.s. | — |
| **Δ 결심지연(To-Be−As-Is)의 변화** | **−3.77 s** [−7.06, −0.48] ★ | +0.53 s n.s. |
| **Δ 격추율의 변화** | −0.56pp [−2.17, 1.05] n.s. | **+0.40pp** [0.02, 0.78] ★ |
| Δ 격추수의 변화 | −0.30 n.s. | **+0.23** [0.01, 0.46] ★ |

**부호 읽는 법**: Δ 결심지연은 음수가 To-Be 우위다. `sawoff − base = −3.77 s`는 **톱니를 끄면
To-Be 우위가 3.77초 더 커진다** = 톱니를 켜면 개선폭이 3.77초 **줄어든다**는 뜻이다. SC2의
격추율도 같은 방향(+0.40pp는 톱니 OFF에서 To-Be 우위가 더 크다는 뜻)이다.

**저부하 SC1·SC2에서도 축소 방향이 유의하게 확인된다** — 효과 크기는 작지만(결심지연 3.8초 ·
격추율 0.4pp) 부호가 일관되고, 그 원천이 **As-Is 팔의 단독 가속**임이 팔별 분해로 드러난다
(As-Is +3.89 s ★ vs To-Be +0.12 s n.s.). 원자료: 스크래치 `paired075-sc{1,2}.txt`.

## 한계

1. **전역 동기 시계 가정.** codex와 동일하게 모든 센서의 보고 시점이 `t = 0`을 공유한다고 가정한다.
   실제로는 센서별 위상(phase)이 독립적으로 무작위다. 위상 난수를 도입하면 codex와의 bit 비교가
   불가능해지고 RNG 스트림이 하나 더 늘어난다. **정본 일치를 우선했다** — `docs/params.md`
   IADS-LINK-SAW-01에 개념적 한계로 기록.
2. **결정적 함수 — MC 변동의 원천이 아니다.** `staleness`는 난수가 아니라 시각 `t`의 함수다.
   반복 간 변동은 "도착 시각이 seed마다 달라 톱니의 어느 지점을 밟는지가 달라지는" 2차 효과로만
   생긴다. 신선도 자체의 분포를 직접 표집하지는 않는다.
3. **주기 P의 등급이 상한이다.** 톱니 형태는 물리적 성질이지만 P는 codex 스스로
   "ADR-014 모델값(가상 placeholder)"이라 명시한 등급 C 값이다. 파생값도 C를 넘지 못한다.

## 되돌리는 법

딥링크 `saw=0` 또는 화면 상단 「⚙️ 모델 조건」의 「보고 주기 톱니 신선도」 해제.
코드로 되돌리려면 `_linkDelay`의 `report-cycle` 분기 3줄을 제거한다 — `_reportingStaleness`는
그 분기의 유일한 호출자이므로 함께 사문화된다.
