# K-JAMDS C2 시뮬레이터 — KJADS 3대 문제 상황

> ⚠️ **디스클레이머**: 본 프로젝트의 모든 수치·좌표·확률·범위는 공개자료(오픈소스) 기반의 **정책연구용 개념값**이며, 실제 작전자료가 아닙니다. 모든 좌표는 도시·권역 수준 개념좌표입니다. KP-SAM(신궁)·천마(K-31)는 탄도탄 요격 불가로 모델링합니다. FULL 배치에는 주한미군 THAAD/Patriot이 독립 축으로 존재하지만 KAMDOC와 연동하지 않으며, LEGACY 배치에는 THAAD가 없습니다. **본 모델은 지상배치 방공체계 C2에 한정하며 요격기·해상 자산을 포함하지 않습니다(ADR-060).**

한국형 합동방공체계(K-JAMDS)의 As-Is(분절형) ↔ To-Be(통합형) C2 구조를 비교하고,
시나리오 기반으로 C2 프로세스 병목을 도출·시각화하는 웹 시뮬레이터입니다.
DES(이산사건 시뮬레이션) 엔진이 IADS_C2 계열 물리(SNR/RCS·레이더 수평선·센서상태·PSSEK/PIP)
위에서 책임 C2 결정 → 항적 상관·식별 → 사수선정(WTA) → 교전 협조 → 발사대 단위 교전 → BDA의
**native IADS 파이프라인**을 실행하며, **모든 신규 거동은 기능 플래그로 토글**하여
감사 추적을 남깁니다. 2026-07 Phase 6(ADR-061)로 legacy 9단계 파이프라인과 compat 충실도는
폐기되었고, `modelFidelity`는 `iads-c2` 하나입니다.

## 현재 배포·분석 자료 (2026-09-19)

`codex/c2-flow-role-context-20260917`의 표시 개선을 구조 정합성 수정 브랜치에 병합했습니다.
실제 교신·선정·발사 기록, 후보 검토 근거, C2 역할 설명을 구분합니다. 설정 기본값의 타입,
계통별 실패 격리, 상태정보의 유효기간·순서, 명령 발령자·부모 명령 기록은 ADR-100을 따릅니다.

이전 날짜의 보고서·ADR 수치는 해당 측정 조건의 기록으로 구분합니다.

현재 기본 예시(SC3 · seed 29 · **1800초** · 강도 1, ADR-101)의 전체 생성 수는 각 실행 228개입니다.

| 배치 | 모드 | 격추 | 확정 누수 | 종료 미해결 |
|---|---|---:|---:|---:|
| LEGACY | As-Is | 78 | 115 | 35 |
| LEGACY | To-Be | 92 | 101 | 35 |
| FULL | As-Is | 165 | 40 | 23 |
| FULL | To-Be | 173 | 31 | 24 |

종전 기본값 600초에서는 89개 중 22~33개가 종료 미해결이었습니다(미해결률 25~37% → 1800초 10~15%).
600초판과의 비교는 PDF 3-2절에 있고, `?dur=600`으로 종전 조건을 그대로 재현할 수 있습니다.

이는 단일 seed의 재현 예시입니다. 구조 차이의 탐색은 PDF에 수록한 배치별 20쌍의 seed 차이와
95% 신뢰구간을 사용하며, 확정 누수 감소와 종료 미해결 증가를 구분합니다.
같은 seed의 To-Be − As-Is 누수율 차이는 LEGACY 평균 −5.512%p(95% CI −6.258~−4.766),
FULL −3.195%p(−4.180~−2.209)입니다. 분모는 각 실행의 생성 항적 수이며, 개념 모델의
해당 설정에서 얻은 탐색적 결과입니다. 누수가 증가한 seed는 LEGACY 0개, FULL 1개입니다.
600초에서는 각각 −1.784%p · −2.136%p였습니다 — 관측 시간이 결과의 크기를 바꾸므로, 수치를 인용할
때는 관측 시간을 함께 적습니다.

```bash
node docs/analysis/2026-09-19-current-reports/analysis-run.mjs --workers 2
node docs/analysis/2026-09-19-current-reports/c2-analysis-run.mjs
node docs/analysis/2026-09-19-current-reports/report-gen.mjs      # 두 결과를 한 문서로 (교차 검산 포함)
node docs/analysis/2026-09-19-current-reports/render-reports.mjs
node docs/analysis/2026-09-19-current-reports/verify-pdfs.mjs
node scripts/export-params-xlsx.mjs
```

PDF 렌더에는 로컬 Chrome과 Playwright가 필요합니다. XLSX 갱신은 Artifact Tool로 기존 시트·서식을 보존하며,
설치 위치를 자동으로 찾지 못하면 `KJ_ARTIFACT_NODE_MODULES`로 관리된 `node_modules` 경로를
지정합니다. 명시적 `--lite` 대체 방식은 기존 서식·수식을 보존하지 않는 재생성이므로 구분합니다.

- 구 legacy 배치(24+40노드 wire)와 그 L16 12초·KVMF 30초 링크는 ADR-061로 폐기 — 판정 근거는

지도에서는 동일 좌표의 포대·ECS·MFR을 하나의 공동 사이트 마커(자산 수 배지)로 겹쳐 표시하고,

OFF입니다. Leaflet 없는 SVG fallback도 같은 중첩 표시와 범위 링 토글을 지원합니다.

## 사용 흐름

```
① 시나리오·배치(고해상도 6종)·체계모드(토글)·강도 선택
② [▶ 시뮬레이션 시작] → 지도 위 위협궤적·노드 재고 링 실시간 애니메이션
   (백그라운드: DES 양모드 비교 — iads-c2 물리는 계산량이 커 자동 MC를 생략)
③ 재생 종료(또는 [결과 보기]) → 결과창: 요약·As-Is↔To-Be 비교·
   도출 병목·누수 사유·흐름 funnel·중복교전 위험·노드 관측통계
```

- 체계 모드는 **단일 토글 스위치**(off=As-Is 분절형, on=To-Be 통합형).
- 5개 탭: **[시뮬레이션]**(지도·실행·결과창) · **[분석]**(합계 한 줄 · **탐지→발사 파이프라인 시간표** · 항적 병렬 대조) · **[C2 구조]**(As-Is↔To-Be 계층도·항적 재생) · **[Monte Carlo]**(수렴·유의성·민감도·임계 전환점) · **[근거자료·제약검증]**(파라미터 근거·제약 어서션).
- **항적 로그는 축별 레인으로 갈라 읽습니다**(ADR-081) — 한 항적에 지휘관이 동시에 3~4개
  붙기 때문에(통합축 + 국지축 2곳 + 도메인 제대 + 센서) 한 줄로 이으면 같은 항적이 여러 번
  도는 것처럼 보입니다. 센서 레인은 기본 접힘입니다.
- **시간표는 한 장입니다**(ADR-083 — 종전 「결심시간 분해」·「구간별 소요시간」 두 표를 합쳤습니다).
  탐지를 0초로 놓고 발사까지를 ①C2 입력 → ②C2 처리 → ③**교전 협조** → ④교전 가능 상태 대기 →
  ⑤C2 출력로 나눕니다. 각 행의 **성격 배지**는 구간 설명이며 구조의 인과적 기여를 판정한
  결과가 아닙니다. 잔여 구간 정의에 따라 **①+②+③+④+⑤ = 합계**가 항적마다 성립합니다.
- **④ 대기 구간은 관측 시각의 잔여 구간입니다.** 비행 기하·사격통제·자원 상태·재평가 등이
  함께 작용하므로 시간 길이만으로 원인을 확정하지 않습니다. 상류 처리시간이 바뀌면 대기의
  시작점과 이후 사건도 달라질 수 있습니다. ③ 협조 외에도 C2 처리시간에 운용자 성분이
  포함됩니다. 구간별 차이는 같은 코호트·분모에서 비교하고, 구조의 인과 효과와 구분합니다.
- 엔진의 `meanTimeToEngageSec`는 **생성→최초 실제 발사**, `meanDecisionDelaySec`는
  **탐지→최초 실제 발사**의 표본 평균입니다. 이름만 보고 최초 명령 시각이나 인간 결심시간으로
  해석하지 않습니다. 새 PDF에는 실제 발사 항적 수와 시간 재구성이 가능한 표본 수를 표시합니다.

## 실행 방법

정적 웹 페이지이므로 별도 빌드가 필요 없습니다. 두 가지 방법이 있습니다. FULL 배치·Monte
Carlo처럼 계산량이 큰 실행은 **방법 A**를 사용해야 DES·MC·민감도·전환점 계산이 Web Worker로
분리되어 지도와 컨트롤이 계속 반응합니다.

**외부 다운로드가 필요 없습니다.** 지도 라이브러리(Leaflet 1.9.4)는 `vendor/leaflet-1.9.4/`에
동봉돼 있습니다. 인터넷이 필요한 것은 지도 **배경 타일**뿐이며, 타일이 없어도 Leaflet은
정상 초기화되어 자산 마커·범위 링·연결선과 **위협 궤적 재생 애니메이션이 모두 동작**합니다
(배경만 비어 보입니다). `window.L` 자체가 없을 때만 SVG 개념도로 대체되며,
`?svgFallback=1`을 붙이면 그 대체 화면을 일부러 재현할 수 있습니다.

### 방법 A — 로컬 서버 (권장)

```bash
./scripts/serve.sh                 # http://127.0.0.1:8000 접속 (포트 변경: ./scripts/serve.sh 9000)
```

> 🪟 **Windows 사용자**: `serve.sh`는 bash 전용이라 더블클릭하면 **메모장이 열립니다**(Windows에
> `.sh` 실행기가 연결돼 있지 않기 때문 — 파일 연결을 바꿔도 해결되지 않습니다).
> **`scripts\serve.bat`을 더블클릭**하세요 — Windows 기본 탑재 PowerShell(.NET HttpListener)로
> 같은 서버를 띄웁니다. **Python·Node·git·bash 설치가 전혀 필요 없습니다.**
> 포트 변경은 `serve.bat 9000`, 중지는 창에서 Ctrl+C.
> 서버 없이 보려면 **방법 B(단일본 HTML 더블클릭)** 가 가장 간단합니다.

`scripts/serve.sh`는 `python3 -m http.server`를 127.0.0.1에 명시적으로 바인딩합니다. `--bind` 없이
직접 실행하면(특히 macOS) IPv6 주소(`http://[::]:8000/`)가 떠서 클릭해도 안 열리는 경우가 있는데,
이 스크립트를 쓰면 항상 바로 열리는 링크가 출력됩니다. (`python3 -m http.server 8000 --bind 127.0.0.1`도 동일.)

서버 실행에서는 IADS 커널(ES module, `js/model/iads/`)이 모듈로 적재되고, ES module 기반
`js/workers/sim-worker.mjs`가 연산을 전담합니다(구형 환경용 `js/workers/sim-worker.js`는 Classic
Worker 호환 경계). 입력 강도 슬라이더는 120ms 디바운스, FULL 지도는 10fps(LEGACY 30fps)·재고 링
4Hz로 제한해 드래그와 애니메이션의 경합을 줄였습니다. 화면의 `계산 모드`가 `Web Worker`인지
확인하면 됩니다. 모든 실행은 SNR·RCS·레이더 수평선·섹터·센서 4상태, coarse-scan 추적상실
hazard/신선도, 센서별 탐지·추적·FC 거리와 range·aspect PSSEK/PIP, 상관·식별과 명시적 C2 명령
수명주기를 사용합니다(iads-c2가 유일 충실도 — ADR-061).

### 프로토타입 — [지휘 흐름] (`prototype/command-flow.html`)

지도가 아니라 **계선(간선) 위에서 전문이 움직이는 것**을 보는 관측 화면입니다(ADR-084~086).
[전체 흐름] 보기는 배치 전체를 세워 노드 케파 링·큐 꼬리·드롭 섬광으로 병목을 보여주고,
[항적 개별] 보기는 항적 하나의 전문 이동을 따라갑니다 — 점이 선을 건너는 시간이 곧 그
계선의 실제 지연이라, 데이터링크와 음성·문자·VTC의 차이가 눈으로 바로 갈라집니다.
계선을 클릭하면 그 계선의 **매체를 갈아 끼우는 반사실 실험**(ADR-084 ②)을 걸 수 있습니다.

- **역할 설명과 실제 기록을 구분합니다.** 점선 역할 연결은 카탈로그의 역할 맥락이며 실제
  전문 전달을 뜻하지 않습니다. 교신 연결선은 기록된 흐름에서, 후보 검토·실패 요약은 별도
  근거에서 읽습니다. 후보 평가에 등장한 자산만으로 명령 연결선을 만들지 않습니다.
- 그래프 아래 **교신·선정·발사 기록**에서 항적을 고르고, 기록을 클릭하거나 이전/다음
  버튼으로 해당 시각을 확인합니다. 현재 상태는 재생 시각 기준이고, 옆의 검토·실패 요약은
  실행 전체 기준입니다. 최초 실패 사례의 자산은 전체 후보 목록이나 최종 명령 대상을 뜻하지 않습니다.
  **제목의 기록 열기/닫기**를 누르면 패널을 접거나 펼칠 수 있습니다. 기본은 펼침이며,
  접은 상태에서도 제목은 남습니다. 제목에 포커스를 두고 Enter 또는 Space로 조작할 수 있고,
  보기 전환 중에도 열림 상태를 유지합니다. 패널을 접으면 그래프의 세로 공간이 늘어납니다.
- 상태줄은 **전체 생성·격추·누수·종료 미해결**과 **상세 기록 수/전체 수**를 함께 표시합니다.
  항적 기록과 흐름 기록의 절삭을 각각 알리며, 지도·목록·복수 사수 집계가 표본에 한정되는지
  표시합니다. 화면 기본 `traceCap=300`을 전체 생성 위협 수로 해석하면 안 됩니다.
- 화면 기본값은 `SC3 · LEGACY_NORMAL · seed 29 · 1800초 · 강도 1`입니다(ADR-101 — 종전 600초는 `?dur=600`).
  FULL 배치는 1800초에서 브라우저 계산이 30초쯤 걸립니다. `pipe/icc/lx/aim/par`
  는 ON, `floor/ecs/issue`는 OFF입니다. `par=1`을 생략해도 같은 boolean 설정이 적용되며,
  기본 숙련도에서 IAOC 운용자 성분은 30초입니다. seed 29는 재현 예시로 사용합니다.

- **적의 표적**은 축선당 1점이 아니라 **조준점 10점**입니다(ADR-097 `aim` — 이 화면만 기본 ON).
  종전에는 착탄이 6점에 묶여 **방어 배치가 시험되지 않았습니다**(FULL 84포대 중 65개가 한 발도
  안 쏨). 조준점은 IADS_codex `HANBANDO_FULL_16T` 세트를 좌표 그대로 옮긴 것이고, 지도에 황색
  십자로 섭니다. 탄도탄만 받으며 배정은 결정론이라 난수 소비가 늘지 않습니다(CRN 쌍대 유지).
  켜고 끈 결과는 같은 seed·배치·다른 플래그를 고정해 비교합니다. 조준점 변화는 위협의 공간
  조건도 바꾸므로, 그 차이를 C2 구조 단독 효과로 해석하지 않습니다. 끄려면 `?aim=0`.
- **탄도탄 발사점**은 축선 연장선에서 시작합니다(ADR-091 `lx` — 이 화면만 기본 ON, 엔진 기본은
  OFF). 종전에는 탄도탄이 이미 모든 센서의 시야 안에서 생겨나 **그린파인 900km 조기경보가 한 번도

  먼저 보므로 손대지 않습니다. 끄려면 `?lx=0`.
- 상단 **[LEGACY] / [FULL]** 스위치로 배치를 바꿉니다. LEGACY 64노드(포대 15)는 계선 흐름을
  읽기 좋고, FULL 251노드(포대 84)는 배치 자체를 시험합니다.
  > ⚠️ **두 배치의 수치를 섞어 인용하면 안 됩니다.** 배치 이름을 스위치와 실행 상태줄
  > 두 곳에 표시합니다. FULL은 계산량이 크며 메인 스레드에서 실행됩니다.
  > 무력화 배치(MCRC_DOWN·KAMDOC_DOWN)는 `?dep=`로 고릅니다.
- 모든 점의 출발·도착 시각은 `KJ.runDES({flowTrace:true})`가 기록한 **실제 실행값**입니다
  (flowTrace는 순수 관측 채널 — RNG·동역학 불변, ADR-084 ①).
- **To-Be의 MCRC·KAMDOC 부하는 도메인별 통보 처리입니다.** IAOC와 같은 시각에 항적을

## native IADS C2 파이프라인 + 정책 계층 이식 (ADR-056~059)

DES 엔진(`js/engine/sim-engine.js`)은 개별 위협 객체를 이벤트 구동으로 흘려보내
**관측** 이용률·대기열·드롭·격추/누수를 수집합니다(C2 노드는 M/M/c/K 대기행렬 — 서버 c·지수 서비스·용량 K 초과 시 드롭).

```
센서 스캔(SNR/RCS·수평선·섹터) → 항적 생성·상관·식별 → 책임 C2 결정(위협종류×아키텍처×생존상태)
  → 교전 협조(ADR-058: LOCAL_AD 축 협조 계선·위임 — 상하 관계 아님, ADR-098) → 사수선정 WTA(ADR-059: 모드 차등)
  → PIP/PSSEK·발사대 탄약/재장전 → 교전(SLS 최대 2발) → BDA → 재교전/누출 분류
```

legacy C2 이론은 **정책 계층으로 이식**되었습니다. 본 앱의 「⚙️ 모델 조건」에 있는 여덟 가지는
기본 ON입니다(ADR-065~072). 엔진·본 앱·지휘흐름 화면의 기본값이 서로 다른 플래그는 아래에
구분합니다. 효과 비교 시 플래그를 하나씩 바꾸고 나머지 입력과 seed 집합을 고정합니다:

## 감사 추적 방법론 — 구현 계약과 연구 가설의 분리

구현 검증은 설계한 절차·계정·설정이 코드에서 지켜지는지 확인합니다. 모델 타당성 검토는 그
설계와 개념값이 연구 질문에 적합한지 별도로 판단합니다. 회귀 검사를 통과했다는 사실만으로
실제 C2의 효과가 입증되지는 않습니다. 변경 영향은 방향과 관계없이 ADR과 커밋 로그에 기록합니다.

- **기능 플래그 + 기준선 지문**: 모든 개선은 토글 가능하며, 기준선은
  `tests/hires-baseline.json`(SHA-256 6케이스)이 고정합니다. **ADR-065에서 기본값 3종을 ON으로
  전환하며 기준선을 재수립**했고, 그에 따라 ADR-056 지문의 의미가 "OFF == 도입 전"에서
  **"OFF == 현행 기준선"**으로 약해졌음을 명시합니다(ADR-061의 이관 시점 약화에 이은 두 번째).
- **2-베이스 편향 원장(bias ledger)**: 각 플래그를 주 베이스({056+057 ON})와 전-OFF 참조 베이스
  양쪽에서 토글해 지표 이동을 기록 — 낡은 기준선이 효과를 3~4배 부풀리는 것을 실측으로 노출.
- **반증 실험(falsification)**: "정의상 To-Be만 좋아지는" 변경은 As-Is에도 동일 로직을 적용한
  반사실 실행과 비교합니다. ADR-059에서 비용항 단독 효과가 작게 관측된 기록은 해당
  조건에 한정합니다. 현행 구현 검사는 비용항의 적용 범위와 통제 후보의 순위 변화를 확인하며,
  특정 seed에서 결과가 반드시 같거나 어느 모드가 우세해야 한다고 요구하지 않습니다.
- **에스컬레이션**: 어떤 변경이 To-Be 개선폭을 20% 이상(상대) 움직이면 보고서 최상단에 🔴로 명시.
- **구현 계약**: 동일 입력의 결정론, 전체 생성 수와 격추·누수·미해결의 합계, 관측 ON/OFF의
  동역학 불변, 계통별 실패 격리, 메시지의 유효기간·순서, 화면과 실행 설정의 일치를 검증합니다.
  신궁·천마의 탄도탄 교전 불가는 명시된 **모델 범위 제약**으로 별도 검사합니다.
- **반증 가능한 연구 가설(G6)**: ①As-Is의 지배 병목이 교전 협조인지, ②To-Be에서 병목이
  무기체계로 이동하는지, ③무인기 비용 비대칭이 남는지는 **실험 결과로 검토할 가설**입니다.
  어느 가설도 회귀 통과 조건으로 고정하지 않습니다. 반대 결과나 차이 없음도 유효한 결과이며,
  결함 여부는 위 구현 계약 위반의 증거로 판단합니다.
- **가설 검토 조건**: 동일 위협열·종료 시점·설정으로 짝지은 여러 seed의 차이와 95% CI를
  보고하고, 배치·부하·처리시간의 민감도와 종료 미해결 비율을 함께 확인합니다. 단일 seed의
  우열·드롭 발생이나 노드 부하만으로 C2 구조의 우수성을 판정하지 않습니다. 지문 변화는
  변경 원인을 조사하는 신호이며, 이전 결론을 되살리기 위한 매개변수 조정의 근거가 아닙니다.
- **결정 기록(ADR)**: 설계가 갈린 지점마다 `docs/adr/` — 맥락·선택지·결정·근거·결론 영향(수치)·되돌리는 법.

## 설계 원칙: 병목은 고정이 아니라 도출된다

병목 위치는 하드코딩되지 않습니다. **시나리오 부하(λ)·모드별 토폴로지·노드 처리용량(M/M/c/K)**
로부터 계산하며, 시나리오·강도·모드·seed를 바꾸면 병목 위치가 함께 바뀝니다.

- **해석적(`analysis/bottleneck.js`)**: 부하를 그래프에 전파해 정상상태 M/M/c(Erlang-C) ρ·Wq — 빠른 개략 분석.
- **DES(`engine/sim-engine.js`)**: 개별 위협을 이벤트 구동으로 흘려 **관측** 이용률·대기열·드롭·격추/누수 수집 — 실증적 병목·결과지표.

임계값(주의 ρ≥0.7, 병목 ρ≥0.9, 포화=드롭 발생 — 근거 `docs/params.md` ENV-RHO-THRESH-01)을 초과하는 지점을 병목으로 **도출**합니다.

## 딥링크 스킴

`#tab=<sim|analysis|decision|mc|data>&sc=<시나리오ID>&mode=<asis|tobe>&dep=<배치ID>&appr=<0|1>&disp=<0|1>&south=<0|1>&linkv2=<0|1>&rp=<0|1>&cop=<0|1>&saw=<0|1>&sdf=<0|1>&x=<강도배수>&seed=<정수>&dur=<초>`

- `dep`은 고해상도 6종 ID(기본 `HANBANDO_LEGACY_NORMAL`). 구 딥링크의 `dep=legacy`·MINI ID·
  `fid=` 파라미터는 기본값으로 자동 흡수됩니다(ADR-061).
- `appr` · `disp` · `south` · `linkv2` · `rp` · `cop` · `saw` · `sdf`는 **전부 기본 1(ON)** 입니다
  (ADR-065~072). **`=0`으로 끄면 각각의 구 기본값이 재현**되며, 감사·반증 목적으로만 쓰십시오 —
  화면 상단 「⚙️ 모델 조건」 접힌 영역의 체크박스와 같은 스위치입니다.
- `appr=0` 교전 협조 계선 해제(ADR-058·065). 끄면 As-Is 협조 대기가 0이 되고, ⑥⑦ 교전 협조 지표는
  0이 아니라 **"미측정"**으로 표시됩니다(ADR-062).
- `disp=0` 표적권역 산포 해제(ADR-063·065). 끄면 같은 축선의 모든 위협이 seed와 무관하게 정확히
  같은 한 점으로 향합니다. ⚠️ 산포는 표적권역 **내부**만 다양화하며 새 표적(부산·대구 등)을
  만들지 않습니다 — 그것은 축선 추가(`south`)의 몫입니다.
- `south=0` 남부 종심 축선 해제(ADR-064·065). 끄면 표적 회랑이 3권역으로 줄고 남부 14문이
  어떤 seed에서도 교전 기회를 갖지 못합니다.
- `linkv2=0` 링크 의미론 정합 해제(ADR-057·066). 끄면 As-Is 센서 보고가 일률 16초로,
  To-Be 전 링크가 2초로 돌아가는 구 설정을 사용합니다. 현행 센서별 보고주기와 다른 조건입니다.
- `rp=0` 레이더→C2 보고 주기 대칭 해제(ADR-067). 끄면 To-Be 보고 링크만 전부 1초가 되어
  같은 그린파인이 To-Be에서 16배 빨리 보고합니다(codex `ifcn:1` 해석).
- `cop=0` 교전현황 공유 COP 해제(ADR-056·068). 끄면 통합 지휘소가 받은 교전현황을
  중복해소 판단에 사용하지 않습니다. 중복 수의 변화는 실행 결과에서 측정하며,
  As-Is는 어느 쪽이든 bit-exact로 동일합니다.
- `saw=0` 보고 주기 톱니 신선도 해제(ADR-069·072). 끄면 센서 보고 지연이 주기 P로 **고정**됩니다.
  켜면 실제 주기 갱신처럼 그림 나이가 `[0, P)` 톱니로 변동해 평균이 `P/2`로 내려갑니다 —
  codex ADR-014 정본 형태입니다. 양 모드에 동일하게 적용되므로 한쪽 팔만 빠르게 하지 않습니다.
- `sdf=0` 자위권 사격 해제(ADR-071·072). 끄면 상급·원격 화력통제가 없는 포대는 **자기 머리 위로
  떨어지는 탄도탄에도 사격하지 않습니다**. 켜면 예측 탄착점이 포대 10 km 이내인 탄도탄에 한해
  자체 판단 경로를 허용합니다(codex ADR-050 3단 발사 사다리 ③). 이 경로는 통상 교전 협조를
  우회하므로, 지휘 경로의 발사와 따로 집계하고 모드별 효과는 실험에서 확인합니다.
- `engageOnRemote`(ADR-070)는 **딥링크·토글이 없습니다** — `nativeWtaMode`·`approvalChainTobe`와
  같은 반사실 전용 플래그라 `scripts/experiment-run.mjs --features`로만 켭니다. 기본값이 아닌 사유는
  ADR-070 참조.
- 구 `tab=map|scenario|des|playback`은 `sim` 탭으로 흡수됩니다.

### 고해상도 결과의 요격 실패율 읽기

결과 모달은 `격추`, `확정 누출`, `관측 종료 미해결`을 전체 생성 위협 기준으로 따로 표시합니다.
`global.killRate/leakRate`는 종료 시점 미해결을 제외한 **해결분 기준** 파생지표이므로, 전체 생성
기준 비율과 구분해야 합니다. native 경로는 무한 재교전을 막기 위해 표적당 전 책임 C2 축 합산
최대 2발을 발사합니다. 경도·위도 진행률과 체공시간은 아직 개념 축선/dwell 함수이고 false
merge/split은 포함하지 않습니다(§6 미충족 후속 과제 — ADR-061). 따라서 절대값은 전술 성능치가
아니라 배치·모드 비교값으로만 사용하십시오.
