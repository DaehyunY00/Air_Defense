# ADR-101 — 지휘 흐름 화면의 기본 관측 시간을 600초에서 1800초로

> 본 문서의 모든 수치는 공개자료 기반 **정책연구용 개념값**이며 실제 작전자료가 아니다.

- 날짜: 2026-09-19
- 상태: 적용
- 범위: `prototype/command-flow.html`의 `dur` 기본값과 그 단일본, 그리고 이 기본값을 그대로 읽는
  분석 보고서 러너(`docs/analysis/2026-09-19-current-reports/`). 본 앱(`index.html` ·
  `js/core/router.js`)의 기본값은 바꾸지 않는다.

## 맥락

기본 600초에서 SC3 · seed 29 · LEGACY의 89개 항적 가운데 33개(As-Is)가 「종료 미해결」로 남았다.
항적의 3분의 1 이상이 결과가 확정되기 전에 관측이 끝난 것이다. 보고서는 이를 매번 단서로 달아야
했고(「600초 결과를 최종 방어 성과로 해석할 수 없다」), 화면을 처음 여는 사람은 격추·누수 수만
보고 나머지 3분의 1을 놓치기 쉬웠다.

사용자 결정(2026-09-19): 모의설정의 기본값을 1800초로 한다. 이어서 분석 보고서도 1800초 기준으로
다시 작성하기로 했다(같은 날의 별도 요청).

## 결정

1. `PARAMS`의 `dur` 기본값, 입력칸의 초기값, 입력이 비었을 때의 되돌림 값을 모두 1800으로 한다.
   `?dur=600`을 주면 종전 조건이 그대로 재현된다(실측: 격추 27 / 누수 29 / 미해결 33 — 종전과 같다).
2. 분석 러너는 기본값을 화면에서 직접 읽으므로 따로 고정하지 않는다. 600초로 고정돼 있던 C2 기록
   실행도 화면 기본값을 따르게 한다.
3. 엔진·물리·카탈로그는 바꾸지 않는다.

## 결과와 주의

- 기본 실행(SC3 · seed 29 · LEGACY · As-Is)은 생성 228개 · 격추 78 · 누수 115 · 종료 미해결 35가 된다.
  미해결의 **비율**은 37%에서 15%로 준다. 미해결이 없어지는 것은 아니다 — 관측창을 늘리면 새 위협도
  함께 늘어난다(동일 코호트 추적이 아니다).
- 화면의 항적 기록 상한(`traceCap=300`)에는 걸리지 않는다(228/228).
- 브라우저 계산 시간(실측, 같은 기계): LEGACY 1.0초 → 3.9초, FULL → 31초. FULL은 화면이 이미
  「계산 20초+」를 알린다. 메인 스레드에서 돌므로 그동안 화면이 멈춘다.
- **seed 29는 600초 조건에서 고른 재현 예시다(ADR-084 §추기, ADR-100).** 1800초의 대표 표본이라는
  뜻이 아니며, 구조 차이는 20개 쌍대 seed로 읽는다.
- 이전 날짜의 보고서·ADR 수치는 600초 조건의 기록이다. 1800초 수치와 섞어 인용하지 않는다.

## 보고서 재실행에서 확인한 것 (소스 `3874d4c`, 엔진·어댑터 해시는 600초판과 같음)

- 20개 쌍대 seed의 To-Be − As-Is 누수율 차이: LEGACY −1.8 → **−5.5%p**[−6.3, −4.8],
  FULL −2.1 → **−3.2%p**[−4.2, −2.2]. 누수 감소/동일/증가 seed 수는 14/4/2 → 20/0/0, 12/3/5 → 18/1/1.
  관측 시간이 구조 차이의 **크기**를 바꾼다 — 수치를 인용할 때 관측 시간을 함께 적는다.
- 600초판의 누수 원인 표에 없던 **탄약 소진**이 주요 원인으로 나타난다(LEGACY 28/24건, FULL 21/18건).
  600초 관측으로는 보이지 않던 제약이다.
- 1800초에서는 명령 계보가 없는 자위권 발사가 최초 발사인 항적이 생긴다(네 기준 실행 합계 2개).
  엔진의 탐지→발사 집계에는 들어가고 기록 계보 재구성에서는 빠지므로, 보고서 생성기의 교차 검산을
  「표본이 같은 실행은 평균도 같다 · 빠진 수는 기록된 제외 사유의 합과 같다」로 고쳤다.
- 일반 분석 182셀의 계산 시간은 370초 → 1,595초(worker 2개).

## 검증

- `tests/command-flow-config.test.mjs`: 기본 URL과 잘못된 `dur` 입력이 1800을, `?dur=600`이 600을 준다.
- 실제 Chrome에서 단일본을 열어 입력칸 초기값 1800, 기본 실행의 기록 228/228, 페이지 오류 0건을 확인.
