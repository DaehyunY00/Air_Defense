# ADR-072 — 톱니 신선도·자위권 사격 기본 ON + 모델 조건 토글 UI 접기

> 본 문서의 모든 수치는 공개자료 기반 **정책연구용 개념값**이며 실제 작전자료가 아니다.

## 맥락

ADR-069(톱니 신선도)·ADR-071(자위권 사격)을 플래그 뒤에 기본 OFF로 구현했다(불변 규칙 1).
사용자 판단(2026-07-30): "069, 071의 경우 기본 ON으로 설정되어야 하고, 마찬가지로 UI에서는
보이지 않아야 하는 게 맞지 않아?"

동시에 앞선 지시(2026-07-29)로 기본 ON 토글 6개는 이미 **UI에서 접혀** 있었다
("토글은 유지, UI에서만 감춤"). 새로 기본 ON이 되는 2개도 같은 취급이 필요하다.

## 결정 1 — 기본 ON 전환

| 플래그 | ADR | 기본 ON 사유(판정 기준) |
|---|---|---|
| `sawtoothFreshness` | ADR-069 | **정본 정합** — codex ADR-014가 규정한 형태는 톱니이고 상수 P는 Air_Defense가 남긴 1단계 근사였다. 양 모드 공통 적용이라 한쪽 팔만 유리해지지 않는다. |
| `selfDefenseFire` | ADR-071 | **끄면 As-Is를 실제보다 불리하게 표현한다** — 상급 승인이 늦어 발사 마감이 지나면 포대가 자기 머리 위 탄도탄을 그냥 맞는다. 현실 교전규칙에 자위권은 존재한다. |

이로써 **기본 ON 플래그는 8개**가 되었다(ADR-065 3개 → 066 → 067 → 068 → 072 2개).

### 판정 기준을 다시 적는 이유

기본 ON의 기준은 **"결론에 유리한 방향"이 아니다.** 세 가지 중 하나여야 한다:
① 정본 정합, ② 끄면 As-Is를 실제보다 불리하게 표현, ③ 배선 결함 수정.

ADR-071이 이 기준의 시험대다 — 자위권 경로는 승인·협조를 우회하므로 **승인 대기가 존재하는
As-Is를 더 많이 구제하고, 결과적으로 To-Be 개선폭을 줄인다.** 기준 ②를 만족하므로 기본 ON이며,
방향이 불리한 것은 판정에 영향을 주지 않는다. 대조적으로 ADR-070(원격 화력통제)은 To-Be에
유리한 방향인데 **기본 OFF로 남겼다** — 세 기준 어디에도 확실히 들어가지 않기 때문이다.

## 결정 2 — 여덟 토글을 접힌 영역으로

`index.html`의 8개 체크박스를 `<details class="ctl-advanced">` 안에 모으고 요약을
**「⚙️ 모델 조건 (기본값 — 감사·반증용)」** 으로 둔다.

| ID | 라벨 | 딥링크 |
|---|---|---|
| `approval-chain-toggle` | 승인 계선 모델 | `appr=0` |
| `target-dispersion-toggle` | 표적권역 산포 | `disp=0` |
| `southern-axes-toggle` | 남부 종심 축선 | `south=0` |
| `link-semantics-toggle` | 링크 의미론 정본 정합 | `linkv2=0` |
| `sensor-parity-toggle` | 보고 주기 양 모드 공통 | `rp=0` |
| `engagement-cop-toggle` | 교전현황 공유 COP | `cop=0` |
| `sawtooth-toggle` | 보고 주기 톱니 신선도 | `saw=0` |
| `self-defense-toggle` | 자위권 사격 | `sdf=0` |

**감추는 것이지 없애는 것이 아니다.** 이 여덟은 전부 기본 ON이므로 일상 사용에서 건드릴 스위치가
아니고, 상단에 펼쳐 두면 "이 모델은 여덟 개 옵션을 조합해야 쓸 수 있다"는 잘못된 인상을 준다.
반면 감사·반증 경로는 방법론의 핵심이므로 제거할 수 없다 — 접힌 영역 + 딥링크로 **둘 다** 만족한다.

## 배선 — 빠지기 쉬운 지점 목록

플래그 하나를 기본 ON으로 올리려면 **9곳**을 함께 고쳐야 한다. 이 목록은 앞선 전환(ADR-065~068)에서
누락이 발생했던 지점을 축적한 것이다:

1. `js/engine/sim-engine.js` — `ff(key, true)`
2. 같은 파일 — `features` 에코를 **항상 실제 해석값**으로(ON일 때만 신고하면 OFF 감사가 불가)
3. `js/core/router.js` — `DEFAULTS`에 `'1'` + `'0'`만 인식하는 정규화
4. `index.html` — 접힌 영역 안의 체크박스
5. `js/main.js` — 체크박스 초기 동기화 + change 핸들러 + modelConfig
6. `js/ui/panels.js` — modelConfig **+ 캐시 키**(키에 안 넣으면 토글해도 캐시된 결과가 나온다)
7. `js/ui/sim-view.js` — modelConfig + OFF 라벨 표기
8. `js/ui/mc-panel.js` — modelConfig(**ADR-068에서 여기가 빠져 MC 탭이 토글을 무시했다**)
9. `js/ui/map-view.js` — 카탈로그 변형 키가 바뀌는 플래그만(`saw`·`sdf`는 노드·링크 구성을
   바꾸지 않으므로 **해당 없음**)

### 회귀 실패 2건 — 관측 전제가 무너진 것이며 제약 위반이 아니다

전체 게이트에서 `tests/southern-axes.test.mjs`(ADR-064) 어서션 2건이 깨졌다. **지문 재기준선만
갱신하고 전체 게이트를 늦게 돌린 탓에 늦게 발견됐다** — 순서를 지켰다면 재기준선 시점에 나왔을
실패다. 두 건 모두 **임계값을 느슨하게 한 것이 아니라 기전을 특정해 주장의 범위대로 좁혔다.**

기전 특정(플래그 단독 조합 4셀):

| 조합 | ① OFF에서 36.6°N 이남 발사 | ② 남부 축선에 비호·천마 발사 |
|---|---|---|
| ADR-068 기본값(saw·sdf OFF) | **0문** | **0건** |
| saw ON만 | 1문 THAAD_SEONGJU 3발 | 1건 BIHO_CO13→cruise |
| sdf ON만 | 1문 THAAD_SEONGJU 3발 | 1건 BIHO_CO13→cruise |
| ADR-072 기본값(둘 다 ON) | 1문 THAAD_SEONGJU 8발 | 1건 BIHO_CO13→cruise |

**① USFK THAAD(성주 36.13°N)가 발사한다.** ADR-064의 주장은 "**ROK** 남부 배치 자산 14문이
표적 회랑 미도달로 유휴"다. THAAD는 ADR-036 독립축이라 KAMDOC의 표적 회랑 설정과 무관하게 자기
축에서 교전하고, 개념 사거리(~200 km)상 **오산·서울로 향하는 탄도 위협을 성주에서 요격하는 것이
배치 목적 자체**다. 톱니·자위권으로 항적 신선도와 발사 기회가 바뀌자 그 교전이 실제로 발현했다.
→ 어서션을 **ROK 한정**으로 좁히고, USFK 남부 교전은 `NOTE`로 출력해 회귀 시 눈에 보이게 했다.
검증: ROK 한정 시 OFF **0문** · ON **1문(LSAM_SOUTH)** 로 §5의 의도가 그대로 보존된다.

**② 비호가 남부 축선의 순항미사일을 요격한다.** 종전 어서션은 "남부 축선 위협은 전부 장거리
유형이라 단거리 방공 사거리 미달"을 전제로 발사 0건을 요구했다. **그 전제가 틀렸다** — 위협
유형이 장거리라는 것은 *발사 지점*이 멀다는 뜻이고, 종말단계에 대구·부산 상공에 도달한
순항미사일은 그곳 비호의 교전 봉투 안이다. 요격하는 것이 정상이다.
→ 제약의 실제 내용인 **유형 제약**(탄도 위협 발사 0건)으로 대체했다. 발사 분포 `{"cruise":1}`을
어서션 메시지에 실어 다음에 유형이 늘면 즉시 보이게 했다.

**도리적 제약은 깨지지 않았다** — 같은 스위트의 「비호·천마의 탄도 위협 발사 0건」은 처음부터
통과했고(G6④), 이제 남부 축선 한정으로 한 번 더 고정된다.

**부수 발견**: 어서션 메시지가 「신궁·천마」라고 적혀 있었으나 코드는 `BIHO`·`CHUNMA`(비호·천마)를
검사한다. 메시지를 코드에 맞게 정정했다 — 신궁(`KP_SAM`)은 이 어서션의 대상이 아니었다.

## 편향 원장 (paired 30 seed × 1800 s × ×1.5 · LEGACY_HIRES × iads-c2)

두 전환의 단독 효과는 각 ADR의 원장에 있다(ADR-069 · ADR-071). 여기에는 **합산 효과 — 즉
ADR-068 기본값에서 ADR-072 기본값으로 옮겨가며 주 결과가 어떻게 이동했는지**를 기록한다.

원자료: `artifacts/experiment/r75-base-sc{1,2,3}.json`.

| SC3 주 결과 | ADR-068 기본값 (보고서 v3.7) | **ADR-072 기본값** | 이동 |
|---|---|---|---|
| As-Is 격추율 | 38.1% | **41.7%** | **+3.6pp** (톱니 +1.4 · 자위권 +3.2, 상호작용 −1.0) |
| To-Be 격추율 | 56.8% | 57.0% | +0.2pp |
| **Δ 격추율** | **+18.7pp** [17.9, 19.5] | **+15.3pp** [14.5, 16.2] | **−3.4pp (−18%)** |
| As-Is 결심지연 | 162.2 s | 153.2 s | −9.0 s |
| To-Be 결심지연 | 115.9 s | 116.5 s | +0.6 s |
| **Δ 결심지연** | **−46.2 s** | **−36.7 s** | **개선폭 −9.5 s (−21%)** |

| SC1·SC2 | ADR-068 | ADR-072 | 판정 |
|---|---|---|---|
| SC1 Δ 격추율 | −0.6pp n.s. | −0.0pp n.s. | 미분리 유지 |
| SC2 Δ 격추율 | +0.4pp n.s. | +0.0pp n.s. | 미분리 유지 |

**두 전환은 모두 To-Be 개선폭을 줄인다.** 저장소의 기본값 전환 이력에서 SC3 격추율 개선폭은
+27.3pp(v3.5) → +18.7pp(v3.7) → **+15.3pp(v3.8 예정)** 로 단조 감소해 왔다 — 모델을 정본에
맞추고 As-Is를 실제에 가깝게 표현할수록 통합의 이득이 작게 나온다. 감사 관점에서 이것이
**"고쳤더니 좋아졌다"는 비판의 직접적 반례**다.

⚠️ **인용 주의**: 보고서 v3.7의 §4~§7 반사실 표는 ADR-068 기본값 위에서 측정된 것이다.
위 표의 신 기본값 수치와 **섞어 인용하면 안 된다** — 반사실 셀 재측정 후 v3.8에서 통합한다.
