# ADR-113 — 큐 권한(`standbyCueAuthority`): 대기 지시는 준비만, 발사는 지휘소 명령 — 포대 자체 발사는 자위권 ③만

> 본 문서의 모든 수치는 공개자료 기반 **정책연구용 개념값**이며 실제 작전자료가 아니다.

- 날짜: 2026-10-03
- 상태: 채택 (엔진 기본 `'fire'` = 종전 거동 bit-exact · [지휘 흐름] 화면 기본 `'prepare'`)
- 관련: ADR-104(사전대기 큐·긴급발사 ②) · ADR-071(자위권 ③) · ADR-109/110(조기 사수 지정·되먹임) · ADR-112(포대 상태 보고)
- 플래그: `standbyCueAuthority: 'fire' | 'prepare'` · 화면 `?cuefire=0|1`(기본 0 = prepare)

## 맥락

ADR-104의 대기 지시(큐)는 표적 정보와 **발사 권한**을 함께 준다. 큐를 받은 포대는 자기 MFR 사격통제·요격점·잔탄이 갖춰지면 지휘소의
사수 지정 없이 쏜다(긴급발사 ②). 효과척도 결과서(4판)에서 방사포 90개 중 72~75개, 탄도탄 4~8개가 이 경로였고, 긴급발사는 지휘소의
식별 확정과 거의 같은 시각(중앙값 5초 차)에 일어나 지휘소가 「누가 쏠지」를 정하기 전에 포대가 쏘는 구조였다.

사용자 검토(2026-10-03): "원래 방공 체계는 C2가 어떤 포대에 쏘라고 명령하고, 그 포대가 요격을 시도하고 결과를 보고해야 한다. 큐를 받은
포대들이 자기 조건이 갖춰지면 쏘는 것은 결심 권한이 포대에 넘어간 것이다. 표준 절차에 맞추되, 포대가 「내가 맞을 것 같다」고
자위권 차원에서 요격하는 그림은 남겨야 한다."

실측(FULL · seed 29): 긴급발사가 **중복 교전을 만들지는 않았다** — 위협당 긴급 계획이 하나만 살아 있고 정식 계획이 있으면 물러서기
때문이다. 문제는 중복이 아니라 **결심 주체**다.

## 결정

`standbyCueAuthority`를 둔다.

- **`'fire'`(엔진 기본 · 종전)** — ADR-104 그대로. 큐 = 표적 정보 + 발사 권한. 큐를 받은 포대는 ③ 자위권을 타지 않는다(상호배타).
- **`'prepare'`(화면 기본 · 표준 절차)** — 큐 = 표적 정보 + 준비 지시(`_tryIadsStandbyFire`가 발사하지 않는다). 포대는 레이더 등급을 미리
  올리고(획득 이득은 종전대로) 상태를 보고하며(ADR-112), **발사는 지휘소의 사수 지정 명령**(ADR-109 조기 지정 → 「준비되면 쏘라」 →
  포대 발사 → BDA → 교전 현황 보고)으로만 한다. 포대 자체 발사는 **자위권 ③**(ADR-071: 낙하 예측점이 포대 반경 10 km 이내 · 자기 MFR
  사격통제 · 요격 창 마감 직전 · 정식 계획 전무)에 한하며, `'prepare'`에서는 큐를 받은 포대도 ③을 탈 수 있다(②가 없으므로 상호배타가
  성립하지 않는다).

바뀌지 않는 것: 큐 발행 주체·대상·계선·획득 이득(ADR-104 B-1·B-3), 자위권 조건(ADR-071), 조기 사수 지정·되먹임·상태 보고.

## 화면

- `?cuefire=0`(기본): 칩 「사전대기 큐 ON (준비만 · 발사는 지휘소 명령/자위권)」. `?cuefire=1`: 「(발사 권한 포함 · 긴급발사 ②)」.
- 자위권 발사는 로그에 「자위권 발사 ③ — <포대> · 포대 자체 판단」과 조건 설명, 그래프에 **붉은 점선 링 + 「자위권 ③」**으로 그린다
  (종전에는 링만). 긴급발사 ②는 주황 점선 링 그대로.
