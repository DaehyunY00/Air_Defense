# ADR-093 — 승인 파이프라인 현실화: 쏠 수 있을 때 요청하고, 회신은 계선을 되짚어 오며, C2A가 그것을 처리한다

- 상태: 채택
- 일자: 2026-09-01
- 관련: ADR-051(군단 AOC C2A As-Is) · ADR-058(승인 계선) · ADR-081(ECS 교전명령 접수 큐) · ADR-084(지휘 흐름 관측) · ADR-092(C2 처리 시간 바닥)
- 플래그: `approvalPipelineRealism` — **엔진 기본 OFF**(불변 규칙 1 · 재기준선 대상) · [지휘 흐름] 프로토타입은 **기본 ON**(`?pipe=0`으로 해제, 켜진 동안 상태줄 칩 「승인 파이프라인 현실화 ON」 상시 표기)
  - 프로토타입 기본 ON은 「엔진 기본 OFF인 플래그는 프로토타입도 기본 OFF」(ADR-090·092 추기) 규율의 **유일한 예외**다 — 사용자 결정 2026-09-01. 이 화면의 존재 이유가 C2 처리 로그로 결심 파이프라인을 읽는 것인데, OFF에서는 AOC·JAOC에 회신 처리 줄이 구조적으로 생기지 않아 없는 절차를 없는 것처럼 보이기 때문이다. 임무 지표(격추·누수)는 16 seed에서 잡음 안임을 실측했다(§수치 영향).

## 맥락 — 「같은 항적에 교전 승인이 두 번」과 「AOC에는 위협판단만」

[지휘 흐름] 프로토타입의 C2 처리 로그가 두 가지를 노출했다(2026-09-01).

1. **MCRC 처리 로그에 같은 항적의 `교전 승인` 작업이 두 줄** — 1군단 방공상황실(AOC)과 수방사
   합동방공상황실(JAOC)이 각자 요청한 것이다(승인 상태는 `지휘관|축` 키로 따로 관리). 두 C2A가
   같은 항적을 독립 처리하는 것 자체는 ADR-051의 As-Is 모델이다. 문제는 그 요청이 나가는 **순서**다.
   `_iadsDecide`가 승인 게이트를 사수 실행가능성 평가 **앞에** 두어, 쏠 수 있는 포대가 없는 항적에도
   승인부터 요청한다. 책임 지휘관 배정(`_resolveIadsCommanders`)은 위협 종류·축 coverage의 정적
   검사뿐이라 수방사는 기하상 닿지 않는 항적의 지휘관이 된다. 엔진 계측(4 seed·SC3 As-Is):
   수방사의 승인 요청은 **51/51건**, 1군단은 62/84건이 항적 전 생애 동안 실행가능 사수 0회 —
   MCRC 승인 부하의 약 80%가 결코 교전으로 이어질 수 없는 요청이었다.
2. **AOC 처리 로그에는 `위협판단·표적할당 준비`만 있다.** 승인이 돌아온 뒤 사수 확정·교전명령
   작성은 AOC의 일인데, 모델은 MCRC 승인 서비스 완료 콜백 안에서 `_iadsDecide`를 직접 불러
   **0초·큐 없이** 끝냈다. 회신이 MCRC→AOC로 돌아오는 계선 지연도 없었다(요청은 음성 20초를
   타는데 회신은 0초). 그 결과 AOC ρ가 0.02 수준으로 나오고, 승인 경로가 AOC 부하와 무관하게
   종결된다 — As-Is에 유리한 편향이다.

방공 운용에서 교전 승인은 "이 포대로 이 표적을 쏘겠다"는 요청이고, 회신은 요청과 같은 채널로
돌아와 지휘소가 접수·확정하는 절차다. 세 가지가 함께 빠져 있었다.

## 결정

`approvalPipelineRealism` 플래그(기본 OFF) 하나로 세 단계를 묶는다 — 같은 결심 파이프라인의
연속 단계라 따로 켜면 조합(8가지)의 해석이 어렵다.

- **(a) 요청은 실행가능 사수가 있을 때만.** `_iadsDecide`의 게이트 앞에서 첫 요청 전(승인 상태
  미정)이면 `commander.batteryIds`를 `_iadsEvaluate`로 훑어 하나도 feasible이 아니면 게이트를
  건너뛴다 — 종전과 같은 후보 평가·재시도·사유 계상으로 내려간다. `_iadsEvaluate`는 순수 함수
  (RNG·계정 무관)라 이 사전 점검은 표본을 바꾸지 않는다(To-Be auto-preauth 유형이 그 증거).
- **(b) 회신은 요청이 간 길을 되짚는다.** 승인 완료 시 `_iadsShortestPath(C2A→승인권자, coord)`의
  간선을 역순으로 같은 매체(`_linkDelay` — 음성 정규 20·σ5)로 `_recordLink`하고 그 합만큼 뒤에
  `IADS_APPROVAL_RETURN`을 건다. 카탈로그에 승인권자→C2A coord 간선은 없다(요청 방향만 선언) —
  회신이 다른 채널을 쓸 이유가 없으므로 되짚는다. 요청이 계선을 타지 않은 경우(To-Be human-on-loop
  감독승인 — 협조 단계 생략, `viaPath` 없음)에는 회신도 0초다. 회신 지연은 `_coordDelay`(결심지연의
  협조 몫)에 누적한다.
- **(c) 회신 접수는 C2A 큐의 작업이다.** kind `approval_return`으로 `_nodeArrive(C2A)` — 서비스가
  끝나야 승인 상태가 `granted`가 되고 `_iadsDecide`(사수 확정·명령)가 이어진다. 그 사이 재시도는
  게이트에서 `wait`로 되돌아가 명령이 새지 않는다. 회신 도착 시 항적이 이미 소멸했으면(MCRC 자체
  교전이 먼저 격추 등) 큐에 넣지 않는다. 드롭은 `approval_dropped`(stage 'return')로 계상.
  ECS의 `directive_reception`(ADR-081)과 같은 대우 — 「접수는 일이다」.

마크: `승인회신발신:승인권자→C2A` · `승인회신접수:C2A` · `승인회신처리완료:C2A`. ADR-083 시간표의
③(승인)은 `승인완료:`까지이므로 불변이고, 회신·처리는 ④(사격통제 성립 대기)의 잔여로 들어간다.

`kindKeys`(노드 통계의 kind 분해)는 ON에서만 `approval_return`을 추가한다 — OFF wire shape 불변.
`global.features`에는 넣지 않는다(ADR-086 원칙).

## 수치 영향 (실측 · SC3 · LEGACY_NORMAL · 600초)

**OFF bit-exact**: 플래그 미지정 결과가 ADR-092 골든 지문과 동일(asis `94ad09ff…` · tobe `6429f951…`),
`hires-baseline` 12/12.

**(a)의 크기 — 요청 시점 실행가능 사수 0인 승인 요청** (엔진 계측, 테스트 고정):

| seed | OFF 요청 → 그중 실행가능 0 | ON 요청(전부 실행가능) | MCRC 승인 도착 |
|---|---|---|---|
| 12345 | 36 → **36** | 9 | 35 → 8 |
| 4 | 58 → **58** | 18 | 57 → 16 |

OFF에서는 **모든** 승인 요청이 요청 시점에 쏠 수 있는 사수가 없는 상태에서 나갔다. 이는 요청
시점이 곧 항적 최초 도착 직후(위협판단 준비 완료)라 아직 PIP가 열리지 않은 탓이다 — 종전 모델은
"먼저 승인받아 두고 창이 열리길 기다린다"였고, 이 ADR은 "창이 열렸을 때 요청한다"로 바꾼다.
승인권자 부하로는 후자가 맞고, 결심 시각으로는 전자가 유리하다 — 이 상충은 §한계에 적는다.

**(b)(c)** — seed 4 As-Is: 회신 링크 MCRC→C2A 14건(평균 20.9초·음성), C2A `approval_return` 도착
4건(요청 18건 중 나머지는 회신 도착 전 소멸 — 대부분 MCRC 자체 교전이 먼저 격추), 마크 순서
`협조개시 < 승인완료 ≤ 회신발신 < 회신접수 ≤ 회신처리완료 ≤ 사수선정` 4/4. seed 12345에서는
회신 6건 전부 도착 전에 MCRC가 격추해 처리 0건 — As-Is의 병렬 교전 구조(공군 축이 먼저 쏨)가
그대로 드러난다.

**16 seed 짝 비교 — As-Is** (Δ = ON − OFF, 95% CI):

| | OFF → ON | Δ |
|---|---|---|
| 격추 | 34.75 → 35.56 | +0.81 ± 2.16 |
| 누수 | 21.25 → 19.63 | −1.63 ± 2.09 |
| MCRC 승인 도착 | 38.6 → 8.4 | **−30.3 ± 3.7** |
| MCRC ρ | 0.394 → 0.204 | **−0.19 ± 0.02** |
| AOC+JAOC 도착 | 39.9 → 41.8 | +1.9 ± 1.2 |
| 그중 `approval_return` | 0 → 1.94 | +1.94 ± 0.62 |
| AOC ρ | 0.017 → 0.019 | ≈0 |
| 평균 결심지연 | 72.0 → 64.8초 | **−7.3 ± 4.0** |
| 평균 협조지연 | 5.57 → 1.81초 | −3.75 ± 1.18 |

읽는 법:
- **MCRC 부하의 절반이 가짜였다.** 승인 도착 −78%, ρ 0.39→0.20. 종전 As-Is의 MCRC 병목 서술은
  이만큼 과장돼 있었다.
- **결심지연이 준다(−7초).** 쓸 수 없는 승인을 기다리며 협조 지연을 쌓던 항적이 사라졌기 때문
  (협조지연 5.6→1.8초). 회신 지연 +20초와 회신 처리 +3.5초가 더해졌음에도 순효과는 감소다 —
  즉 종전 모델의 As-Is 결심지연은 "쏠 수 없는 항적의 헛된 승인 대기"가 부풀린 값이었다.
- **격추·누수는 잡음 안**이다(CI가 0을 포함). 다만 방향(격추↑·누수↓)은 위와 정합한다.
- **AOC ρ는 거의 그대로다.** 회신 처리 작업이 실행당 1.8건뿐이라(요청 대부분이 회신 전 소멸)
  AOC 부하를 눈에 띄게 올리지 못한다. 「AOC 카운트가 올라가야 한다」는 지적은 구조적으로 맞고
  이제 카운트는 올라가지만, 이 시나리오에서 그 양은 작다 — AOC가 한가한 진짜 이유는 MCRC가
  먼저 쏘기 때문이다.

**16 seed 짝 비교 — To-Be** (승인권자 = IAOC, human-on-loop 유형만 해당):

| | OFF → ON | Δ |
|---|---|---|
| 격추 | 43.25 → 43.44 | +0.19 ± 1.80 |
| 누수 | 13.00 → 13.06 | +0.06 ± 1.90 |
| IAOC 승인 도착 | 14.0 → 1.6 | **−12.4 ± 1.8** |
| AOC+JAOC 도착 | 43.6 → 45.2 | +1.6 ± 0.8 (= `approval_return`) |
| 평균 결심지연 | 58.87 → 57.97초 | −0.90 ± 0.68 |
| 평균 협조지연 | 0 → 0 | 0 (회신 0초 — 요청이 계선을 타지 않음) |

To-Be에서도 IAOC 감독승인 요청의 88%가 실행가능 사수 없는 요청이었다. 임무 지표는 불변(IAOC ρ
0.018로 승인 부하가 병목이 아니었기 때문)이고, 결심지연이 소폭 준다. 협조지연 0은 (b)의 규칙
「요청이 계선을 타지 않았으면 회신도 0초」가 그대로 실행됐다는 뜻이다.

## 프로토타입 동반 변경 (관측 전용)

- `?pipe=` 파라미터(**기본 1** — 위 예외). 켜진 동안 칩을 상시 표기해 엔진 기본과 다른 조건임을 숨기지 않는다.
- `JOB_LABEL.approval_return = '승인 회신 처리·교전명령'` — C2 처리 로그에서 AOC·JAOC 줄로 보인다.
- 회신 링크는 기존 매체 표시(음성 = 노란 점선)로 MCRC→C2A 방향의 호(弧)로 그려진다.

## 한계·후속

- **(a)는 "승인을 미리 받아 두는" 운용을 배제한다.** 실제 부대가 PIP가 열리기 전에 선제적으로
  승인을 구해 두는 관행이 있다면 그 시간 이득이 사라진다. 그 관행을 모델링하려면 "요청 조건 =
  N초 안에 창이 열릴 예정"(`readyAt` 기반) 같은 중간 규칙이 필요하다 — 파라미터 근거가 있어야 한다.
- **승인권자의 중복 판정은 여전히 없다.** 두 C2A가 같은 항적에 각자 승인을 받는 것(ADR-051 As-Is)은
  그대로다. (a)로 수방사의 헛된 요청은 사라졌지만, 둘 다 쏠 수 있는 항적이면 둘 다 승인된다.
  MCRC가 "이미 다른 국지 C2에 승인했다"고 거르는 규칙은 별개 결정이다.
- **재시도 폴링(1초)은 큐를 타지 않는다** — 유지. 창이 열리길 기다리는 것이라 서비스 소모가 아니다.
- 회신 처리 서비스 시간은 C2A의 처리 분포를 그대로 쓴다(전용 파라미터 없음). ADR-092 성분과 함께 켜면
  바닥이 적용된다.
- 엔진 기본 ON 전환은 재기준선 대상. 그 전까지 본 앱(index.html)은 OFF.

## 되돌리는 법

`approvalPipelineRealism` 미지정(기본 OFF)이면 종전과 bit-exact. 프로토타입은 `?pipe=0`.
