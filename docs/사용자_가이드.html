K-JAMDS 시뮬레이터 — 사용자 가이드

문서 버전: v3.5 (ADR-065 기본값 전환 반영) · 처음 쓰는 분을 위한 안내입니다. 기술 배경 없이 읽을 수 있게 썼습니다.

먼저 알아둘 것 이 시뮬레이터의 모든 수치는 공개자료 기반의 연구용 개념값입니다. 실제 무기 성능이나 실제 배치가 아닙니다. 화면의 격추율 같은 절대 숫자보다 "현 체계(As-Is)와 통합 체계(To-Be)의 차이"를 보는 도구입니다.

1. 무엇을 하는 도구인가

북한의 항공기·무인기·탄도미사일·방사포 공격 상황을 컴퓨터 안에서 돌려 보고, 우리 방공체계의 지휘통제(C2) 구조가 현재처럼 세 갈래로 나뉘어 있을 때(As-Is)와 하나로 통합됐을 때(To-Be) 결과가 어떻게 달라지는지 비교합니다.

  • As-Is (현 체계) — 탄도미사일은 공군 KAMDOC이, 항공기·무인기는 공군 MCRC가, 전방 근거리 방공(비호·천마)은 육군 군단이 각각 지휘합니다. 서로 상황을 맞추려면 전화·화상회의 같은 느린 협조가 필요합니다.
  • To-Be (통합 체계) — 하나의 통합 지휘소가 모든 위협을 한 화면(공통작전상황도)으로 보고 지휘하며, 정보는 데이터링크로 몇 초 만에 오갑니다.

2. 실행하기

2.1 로컬 서버로 실행 (권장)

./scripts/serve.sh     # 또는: python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속

2.2 단일본 파일

K-JAMDS_시뮬레이터_단일본.html을 더블클릭하면 서버 없이 열립니다. 물리 모듈(IADS_C2 커널)은 단일본 안에 함께 들어 있어 서버 없이도 동일한 물리 시뮬레이션이 동작합니다. 다만 계산을 백그라운드로 분리하지 못해(브라우저 보안 정책) 큰 배치·자동 Monte Carlo는 서버 실행을 권장합니다.

3. 화면 사용법

3.1 상단 컨트롤

체계 모드토글 OFF = As-Is(현 체계) / ON = To-Be(통합 체계)

남부 종심 축선
(기본 켜짐)		대구·부산을 노리는 위협 축선입니다(SC3 전용). 끄면 공격 표적이 서울·오산평택·강릉 세 곳뿐이라 남부에 배치된 포대들이 한 번도 쏘지 못합니다. 개념 사거리상 탄도탄·방사포·순항미사일·전투기만 남쪽까지 도달하며, 무인기·헬기는 자동으로 제외됩니다.
표적권역 산포
(기본 켜짐)		같은 축선의 위협들이 표적 도시 안에서 조금씩 다른 지점으로 향합니다(반경 15km 개념). 끄면 모든 위협이 정확히 같은 한 점으로 갑니다.
승인 계선 모델
(기본 켜짐)		As-Is 승인 절차(군단·수방사 방공통제소 → MCRC 협조 통화 + 승인 대기 + 부하 몰릴 때 권한 위임)를 모델에 포함합니다. 끄면 [분석] 탭의 ⑥⑦ 승인·협조 지표가 "미측정"으로 표시됩니다 — 값이 0이라서가 아니라 그 설정에서는 재지 않기 때문입니다(ADR-062). 현 체계의 승인 지연이 이 연구의 핵심 관측이라 기본으로 켜져 있습니다(ADR-065). 끄는 것은 비교·감사용입니다.
위협 강도 ×위협 수 배수. 크게 할수록 지휘소가 포화되는 모습을 볼 수 있습니다

3.2 진행 흐름

  1. 조건을 고르고 [▶ 시뮬레이션 시작] — 지도 위에 위협 궤적과 교전이 실시간 재생됩니다.
  2. 재생이 끝나면(또는 [결과 보기]) 결과창이 열립니다 — 요약, As-Is↔To-Be 비교, Monte Carlo 신뢰구간, 병목 목록, 누수(막지 못한 위협) 사유가 나옵니다.
  3. [분석] 탭에서 지휘소별 부하(ρ)·대기시간, 협조·중복교전 통계를 봅니다.
  4. [MC] 탭은 같은 조건을 수십 번 반복해 통계적 신뢰구간을 계산합니다.

4.1 기본 성적표

지표일상어 설명좋은 방향
격추막아낸 위협 수높을수록
확정 누출목표 지점까지 뚫린 위협 수낮을수록
관측 종료 미해결시뮬레이션이 끝날 때까지 결말이 안 난 위협(통계에서 별도 처리)—

중복교전같은 위협에 서로 다른 부대가 중복으로 미사일을 쏜 횟수 — 협조 실패의 직접 증거이자 탄약 낭비낮을수록
비용교환비쏜 미사일 값 ÷ 잡은 위협 가치. 1보다 크면 우리가 더 비싼 자원을 쓴 것낮을수록

4.2 자주 오해되는 지표 3가지

지표오해와 바른 해석
협조 지연 몫
(결심 지연 중 통신 협조가 차지한 부분)		 As-Is 결심 지연에서 통신(전화 협조)이 차지하는 몫은 일부에 불과하고, 나머지는 승인권자 앞에 줄 선 대기시간입니다. 즉 "데이터링크만 깔면 해결"은 절반만 맞습니다 — 승인 처리 용량도 같이 늘려야 합니다. 이 분해를 보여주는 것이 이 지표의 존재 이유입니다.
비용교환비 "안 쏘면 교환비가 0이라 최적"이 되는 함정이 있습니다. 반드시 방어효율(지킨 가치 비율, 높을수록 좋음)과 함께 읽으세요. 결과창이 둘을 나란히 보여줍니다.
무인기 교환비(exchangeSat) To-Be로 통합해도 이 값은 1보다 큽니다 — 수천만 원짜리 무인기를 수억 원짜리 미사일로 잡는 비용 비대칭은 지휘구조 통합으로 해결되지 않는다는, 이 연구의 의도된 반증 결과입니다.

4.3 분석 탭 — 지휘소 부하

지표일상어 설명

드롭용량 초과로 버려진 보고·요청 수. 교전현황 공유 채널(전화)의 드롭이 중복교전의 원인

6. 자주 묻는 질문

질문답
격추율이 실제 전력 평가인가요?아닙니다. 좌표·성능·처리시간이 전부 공개자료 기반 개념값이라 절대값은 의미가 없고, 같은 조건에서 As-Is↔To-Be 차이만 의미가 있습니다.
왜 신궁·천마는 탄도미사일을 못 잡나요?물리적으로 불가능한 조합이라 모델이 금지합니다 (제약 어서션으로 고정 — 어떤 설정으로도 풀리지 않습니다).
주한미군 THAAD/패트리엇은 왜 따로 노나요?한국군 지휘체계와 자동 통합하지 않는 것이 현실 반영입니다(ADR-036). To-Be에서도 통합되지 않습니다.
To-Be가 항상 이기도록 만들어진 것 아닌가요?그 반대를 감시합니다 — 변경마다 어느 편이 유리해졌는지 편향 원장에 기록하고, 통합으로도 해결 안 되는 것(무인기 비용 비대칭)을 의도적으로 남겨 반증 가능성을 유지합니다. To-Be에 유리한 수정은 반사실 실험(같은 기능을 As-Is에도 적용)과 함께 보고합니다.
같은 조건인데 결과가 왜 똑같죠?연구 재현성을 위해 난수를 시드로 고정한 결정론 시뮬레이션이기 때문입니다. 다른 표본을 보려면 seed를 바꾸거나 MC 탭을 쓰세요.
