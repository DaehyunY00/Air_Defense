# ADR-098 — 용어 정정: 군단 AOC↔MCRC는 「승인」이 아니라 「교전 협조」

> 본 문서의 모든 수치는 공개자료 기반 **정책연구용 개념값**이며 실제 작전자료가 아니다.

## 맥락

ADR-058이 이식한 `approvalChain`은 As-Is 국지방공 축(군단·수방사 AOC)이 항공기 표적을
교전하기 전에 MCRC와 거치는 단계를 모델링한다. 코드·화면·문서는 이를 「승인 계선」「상급
승인」「승인권자」로 불러 왔다.

사용자 지적(2026-09-10): "군단 AOC와 MCRC는 상급 관계가 아닌 협조 관계라고 보는 게 맞지
않아?" — 맞다. 군단 AOC는 군단장 예하이고 MCRC는 공군 구성군의 교전통제소다. 둘 사이에
지휘 관계는 없다. 모델도 그렇게 만들어져 있다: 계선은 `coord`(협조) 링크이고(ADR-058
§신설 링크 `IADS-APPR-COORD-01`), As-Is 20초는 전선 성능이 아니라 음성·VTC **협조 절차**
시간이다. 「승인」이라는 이름은 항공기 표적의 교전권이 공군 구성군사령관(KAOC) 쪽에 있어
협조의 응답이 사실상 허가 역할을 한다는 데서 왔을 뿐, 상하 관계를 뜻하지 않는다.

「상급 승인」이라는 표현은 읽는 사람에게 지휘 관계를 오해하게 한다.

## 결정

1. **화면·문서 표현을 「교전 협조」로 통일한다.** 승인 계선 → 교전 협조 계선, 승인 요청·회신 →
   협조 요청·회신, 교전 승인 → 교전 협조 완료, 자체교전승인 → 자체 교전결정(협조 불요),
   승인 단계 드롭 → 협조 단계 드롭, 승인 파이프라인 현실화 → 협조 파이프라인 현실화.
   관계는 협조이고 권한은 표적 종류에 따라 비대칭이라는 점을 툴팁·주석에 적는다.
2. **내부 식별자는 바꾸지 않는다.** 플래그 `approvalChain`·`approvalPipelineRealism`, URL
   파라미터 `appr`·`pipe`, 큐 kind `approval`·`approval_return`, 트레이스 마크 `승인완료:`·
   `자체교전승인:`·`승인회신*:`, 실패 코드 `approval_dropped`, 테스트 파일명. 이들은 UI·테스트·
   ADR 20여 건이 문자열로 참조하는 식별자라 바꾸면 이득 없이 회귀 위험만 생긴다. 화면은 항상
   식별자를 표현으로 번역해 보여 준다(`OUTCOME_RULES`·`JOB_LABEL`·sim-view stage 포맷터).
3. 위협 제원의 `approvalLevel`은 xlsx에서 「교전권 보유 C2」로 내보낸다.
