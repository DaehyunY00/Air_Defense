K-JAMDS 시뮬레이터 — As-Is ↔ To-Be 실험보고서

보고서 버전: v3 (2026-07-28 실측) · 코드: v3 브랜치(ADR-055·056 반영) · 실험 원자료: artifacts/experiment/*.json(동일 명령으로 재현 가능)

디스클레이머 모든 수치는 공개자료 기반 정책연구용 개념값 위에서 나온 시뮬레이션 결과다. 절대값은 전술 성능치가 아니며, 의미가 있는 것은 같은 조건·같은 난수에서의 As-Is↔To-Be 차이뿐이다. 이 보고서의 전 수치는 이번 판(v3)에서 재실측한 것이다 — 폐기된 배치(MINI)나 구판 기록은 인용하지 않는다.
🔴 이 판의 가장 중요한 변화 (편향 방향 공지) 이번 판은 To-Be에 유리한 방향의 결함 수정(ADR-056)을 포함한다. 수정 전에는 To-Be가 교전현황을 2초/무손실로 전달받고도 한 번도 소비하지 않아 중복교전이 As-Is보다 많게 측정되고 있었다(§4에서 결함 확정→수정→효과를 전부 공개). 기본값은 여전히 OFF이며, OFF는 수정 전과 비트 단위로 동일하다(SHA-256 회귀 고정). 수정의 단독 효과는 §4.3의 OFF↔ON 대조가 전부이고, 임무 결과(격추·누수)는 통계적으로 움직이지 않았다.

1. 실험 설계

요소설계
비교 대상As-Is(KAMDOC/MCRC/군단AOC 3축 분절) ↔ To-Be(IAOC 통합·KILL_WEB)
짝지은 실행 (CRN)복제마다 같은 seed로 As-Is/To-Be를 실행 — 위협 도착열이 동일하므로 차이는 구조에서만 나온다
복제 수셀당 30 seed (baseSeed 12345 + 황금비 해시 격자)
실행 조건1,800초 · 위협강도 ×1.5
판정seed별 Δ(To-Be−As-Is)의 95% CI가 0을 제외할 때만 "통계적으로 분리"
셀 매트릭스시나리오 3(SC1/SC2/SC3) × {legacy·compat, LEGACY_HIRES·compat, LEGACY_HIRES·iads-c2} + ADR-056 ON 반사실 2셀
배치·충실도 축의 의미 legacy·compat = 구 64노드 개념배치의 9단계 승인 파이프라인(승인 홉·동적 위임이 모델링된 유일한 경로 — 결심 지연의 구조 분해는 여기서 본다). LEGACY_HIRES = 같은 자산 편성을 고해상도 타입으로 이식(ADR-054)한 주 분석 배치 — compat(개념 교전)과 iads-c2(센서/RCS 물리) 두 충실도를 지원한다. 전투기·이지스·조기경보기가 제외되므로 legacy와 절대값을 직접 비교하면 안 된다. FULL(84포대)은 실행 비용 문제로 이번 판 매트릭스에서 제외했다(모의논리서 §4).
# 재현 (셀당 수 분~수십 분)
node scripts/experiment-run.mjs --cell "sc3|HANBANDO_LEGACY_NORMAL|iads-c2|1.5|30"
node scripts/experiment-run.mjs --cell "sc3|HANBANDO_LEGACY_NORMAL|iads-c2|1.5|30" --features '{"unifiedEngagementState":true}'

4. ADR-056 — To-Be 중복해소 결함의 확정과 수정

4.1 결함 확정 (기본 OFF 상태의 실측)

To-Be의 상급 C2는 축 이름이 KILL_WEB인데, 군단 AOC 교전현황의 유일한 소비 조건이 axis==='MCRC'여서 To-Be는 교전현황을 2초/무손실로 전달받고도 한 번도 소비하지 않았다. paired MC 30 seed로 확정:

중복교전 (LEGACY_HIRES·iads-c2)As-IsTo-Be(OFF)Δ 95% CI
SC18.8017.33+8.53 [+7.22, +9.85] — 0 제외, 우연 아님
SC325.9733.83+7.87 [+5.85, +9.89] — 0 제외, 우연 아님

4.2 수정 — 양방향 COP (플래그 unifiedEngagementState, 기본 OFF)

① 순방향: KILL_WEB도 군단 AOC 교전현황을 소비. ② 역방향: 군단 AOC가 KILL_WEB의 활성 교전을 데이터링크 대표지연 2초 후 COP에서 봄. 순방향만으로는 부족했다 — 잔여 중복이 전부 역방향 (KILL_WEB 선발사→군단 AOC 후발사)이었음을 방향 분해로 확인하고 양방향으로 완성했다. 설계 대안(축 통합안)과의 비교·선택 근거는 docs/adr/ADR-056.

5. G6 — 결론 불변 4종 재산출

결론이번 판 재산출 결과
① As-Is 핵심 병목은 협조·승인 경로(①⑥⑦)유지 — legacy·compat 결심지연 145~153초 중 승인 파이프라인 몫이 지배적(As-Is→To-Be −135초). LEGACY_HIRES에서도 SC3 대기행렬 해소 −87초.
② To-Be 병목은 C2에서 무기체계로 이동유지 — To-Be에서 구조적 실패(책임공백류) 0이 되고 잔여 누수가 timeout(교전창)·missed로 이동(legacy·compat 누수 사유 분포).
③ 무인기 비용 비대칭 미해소 (exchangeSat > 1)유지 — SC2 exchangeSat: legacy 72.6→68.5, LEGACY_HIRES 71.6→70.8. SC1/SC3 iads-c2에서도 20.4~20.6, 4.7~5.8 — 어느 셀·어느 플래그에서도 1 밑으로 내려가지 않음.
④ 신궁·천마 탄도탄 교전 불가유지 — 제약 어서션(tests/constraints.test.js) 통과, 전 회귀 35스위트 856어서션 녹색.

6. 이 판에서 새로 남긴 관측 (후속 분석 대상)

  • SC3 LEGACY_HIRES·iads-c2에서 구조적실패 절대 건수는 To-Be(28~29)가 As-Is(19.9)보다 많다 — ADR-056 이전부터 존재하고 ON이 소폭만 줄인다(29.1→28.1). To-Be의 전체 누수는 절반 이하인데 그중 구조 분류 비중이 높다. 분류 taxonomy 관점의 검토가 필요하다.
  • SC2(무인기)는 어느 구조에서도 미분리 — 교전 수단(SHORAD)의 물리 한계가 지배. C2 지표(결심지연)는 To-Be가 오히려 악화될 수 있다(LEGACY_HIRES·compat +17.8초).
  • As-Is에서 LEGACY_HIRES의 단일 L-SAM이 특정 셀에서 선정되지 않는 관측(ADR-055 §한계) — native 사수 선정의 모드 의존성 분석 과제로 남아 있다.

7. 한계

  1. FULL(84포대) 배치는 이번 판 매트릭스에서 제외 — 셀당 실행 시간 문제. 결론은 LEGACY_HIRES 기준이며 FULL 일반화는 미검증.
  2. 위협 운동학은 개념 축선/dwell 함수(모의논리서 §7) — 절대값 인용 금지.
  3. C2 처리시간 다수가 근거 등급 C — 민감 결론은 파라미터 스윕으로 강건성 확인 필요.
  4. ADR-056은 기본 OFF다 — 본 보고서의 "기본" 수치는 결함이 있는 상태의 수치이며, §4가 그 결함과 수정 효과를 분리 공개한다. 기본값 전환 여부는 후속 결정 사안.
